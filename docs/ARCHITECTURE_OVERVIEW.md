# Punto Architecture Overview

## Runtime Boundaries

Punto now has a small importable `PuntoCore` module and a macOS app target.

- `PuntoCore`: deterministic logic that can be tested without Accessibility permissions or global event taps.
- `Punto`: macOS integration layer: app lifecycle, event tap, Accessibility, clipboard, input source switching, status bar, settings UI.
- `PuntoCoreTest`: executable test harness that imports real `PuntoCore` classes. This exists because the installed CLT Swift toolchain currently does not provide `XCTest` or Swift `Testing`.
- `PuntoTest`: legacy broad simulation harness. It is still useful, but much of it is copy-based, so it should not be the only regression gate.

## Native Punto Switcher Equivalents

The read-only Punto Switcher pass exposed a useful boundary split. Punto now mirrors that split with native Swift types:

- App bundle metadata mirrors Punto Switcher's agent-app shape: the native bundle stays a menu-bar agent and explicitly disables sudden termination so macOS does not opportunistically kill the event-tap process in ways Punto Switcher opted out of. `Scripts/deploy.sh` copies the plist and entitlements before signing so installed metadata stays aligned with source changes.
- `WordTracker`: typed raw word and typed command tail buffer. Terminal capture reads a trimmed tail; auto-correction reads a boundary-preserving tail so `word + separator` can be rewritten without losing prior same-layout context. Completed tokens also carry a native cancellation flag for Punto Switcher-style "do not autoconvert this edited word" behavior.
- `WordTrackingPolicy`: special-key contract for the raw text buffer: Escape/external commands/navigation clear state, Backspace removes one character, Return/Enter/Tab complete a token, and ordinary produced characters continue tracking.
- `WordBoundaryPolicy`: explicit typed-boundary, command-suffix, and terminal-prompt marker rules shared by `WordTracker`, terminal capture, terminal-tail replacement, and tests. It separates true separators such as Space, `-`, `=`, shell operators, and brackets from layout-mapped punctuation such as `/`, `?`, `.`, `,`, `;`, quotes, and square brackets, which must stay inside wrong-layout words. Typed word-boundary checks are layout-aware for both live key events and replayed replacement tails: the Mac Russian path keeps Apple-layout physical punctuation such as backslash/pipe and shifted number-row symbols inside the tracked wrong-layout word instead of clearing `WordTracker` as Windows-only punctuation.
- `Hotkey`, `HotkeyValidationPolicy`, `HotkeyCollisionPolicy`, `ModifierOnlyHotkeyStateMachine`, `KeyDownEventPolicy`, and `EventTapLifecyclePolicy`: shortcut defaults/display/serialization, settings-boundary validation for persisted shortcuts, Punto Switcher-style shortcut editor guards for duplicate shortcuts and raw/shortcut character keycode filtering, pure press-release/debounce/cancel behavior for modifier-only hotkeys, keyDown routing for key-based convert/toggle-case/toggle-auto-correction/cancel-last-conversion hotkeys, paste/undo tracker clearing, ordinary key tracking, and event-tap re-enable decisions after system tap disable events.
- `LegacyHotkeyPolicy`: Punto Switcher shortcut dictionary compatibility for `charKeycode`, `isCommandUsed`, `isAltUsed`, `isShiftUsed`, and `isControlUsed`, including numeric/bool values and string-backed import forms. Native Codable `Hotkey` settings remain the source of truth once present, while legacy `shortcutChangeLayout`, `shortcutChangeCase`, `shortcutSwitchAutocorrection`, `shortcutCancelLayoutChange`, `shortcutFindInYandex`, and `shortcutFindInSlovari` dictionaries are accepted as fallbacks and mirrored on write. The policy also pins the observed shortcut setter/controller/field boundary (`setShortcut:`, `shortcutWithDictionary:`, `resetShortcutsToDefaults:`, per-shortcut setters, `shortcutsPreferencesController`, `switchAutocorrection:`, `cancelLayoutChangeShortcut`, `switchAutocorrectionShortcut`, `changeCaseShortcut`, `setChangeCaseShortcut:`, and `ShortcutField`) so settings compatibility cannot drift silently.
- `SearchShortcutPolicy`: selected-text search URL builder for the Punto Switcher-observed Yandex search and Slovari/translate shortcut path. Search shortcuts are valid as explicit `Not Set` hotkeys by default, can be assigned in settings, capture selected text through the same AX/clipboard safety gate, reject unsafe stale terminal fallbacks, and open the derived URL without modifying text or conversion undo state.
- `SearchbarSettingsPolicy` and `SearchClickPolicy`: Punto Switcher-style `PSSearchbarSettings` compatibility for `ActivationShortcut`, `Autoactivation`, `AutoactivationExceptions`, `AlertShownIn`, `ShouldSearchByDoubleClick`, and `SitesearchPromptCounter`, defaulting to the observed `default-conf.json` values (`true`, `false`, `3`) plus an unset activation shortcut, empty exception list, and the observed initial alert date marker. Click-search policy also pins the observed `canDoSearchClick`, `showSearchWindowAutomatically`, `showSearchWindowSelectedText`, and `setIsClickSearch:` gates and only allows selected-text search after an eligible left double click when both the setting and live AX role capability are true. The runtime path reuses selected-text Yandex search after the double-click selection settles and still clears typed/undo state for all pointer clicks. The Settings window exposes the same `ShouldSearchByDoubleClick` switch under advanced settings, writing back into `PSSearchbarSettings`. The native app does not recreate the proprietary searchbar suggestion UI.
- `ApplicationUpdateSettingsPolicy`: Punto Switcher-style updater/install-state settings boundary for `configVersion`, `isFirstInstallation`, install/update booleans, update-request rate, automatic-check preference, and observed request/shown/statistics dates. It preserves the plist shape and defaults, pins the observed updater key boundary in tests/audit, and does not own network update checks or product-statistics upload behavior.
- `StartupPresentationPolicy`: Punto Switcher-style installer/first-run/welcome/update-presentation gate. It recognizes the observed `--install` launch argument, marks the app as just installed, exits updating state, treats native first launch, legacy `isFirstInstallation`, and observed `isJustInstalled` as welcome triggers, then consumes the install flags after showing onboarding while preserving unrelated updater settings. It also preserves the observed `showUpdateFinishedTooltip` boundary by consuming `isJustUpdated` / `isUpdating` after a native update-finished presentation log, without implementing Yandex network update checks.
- `AccessibilityPreferencesPolicy`: Punto Switcher-style Accessibility-permission opener and alert-copy boundary. The app opens the observed `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` URL first, keeps the observed `System Preferences` AppleScript reveal-anchor fallback for systems or environments where URL opening fails, and preserves the observed modern/legacy Accessibility alert message keys while using native-owned UI copy.
- `PointerEventPolicy`: pointer down events invalidate typed-tail and undo state because a click can move focus/cursor without producing a keyboard event. This mirrors Punto Switcher's click/search awareness without implementing proprietary search suggestions.
- `LayoutConverter`: deterministic layout conversion and target-layout reporting.
- `LayoutDetectionPolicy`: shared single-scalar ASCII/Cyrillic letter classification and the strict 80/20 mixed-layout threshold used by conversion and typed-buffer corruption checks. Combining grapheme clusters, emoji/ZWJ sequences, CJK text, and control characters are treated as non-EN/RU evidence so they can pass through conversion without triggering a layout switch by their first Unicode scalar.
- User-facing `convertWithResult` rejects genuinely mixed English/Russian text as non-applicable; the convenience `convert` API delegates to the same safe decision path so diagnostic callers cannot accidentally apply majority conversion to mixed EN/RU text. Punctuation-only unknown text can still convert through the physical-key majority fallback.
- `CaseConverter`: reversible per-character case inversion for `Cmd+Opt+Z` (`Hello` -> `hELLO` -> `Hello`, while digits/punctuation stay unchanged).
- `ToggleCasePolicy`: replacement and undo-record planning for case toggles, using the same selected-text and terminal-tail replacement methods as layout conversion.
- `TextCapturePolicy`: pure policy for terminal/non-settable selection, prompt-prefixed terminal tail extraction, active clipboard fallback routing after non-settable AX observations, passive clipboard tail validation, typed selected-text replacement transport, blocked-capture stale-state cleanup, and the capture decision matrix for AX/clipboard observations. Non-settable content replacement is allowed through clipboard transport only for observed content surfaces (`AXWebArea` and the Mail/Parallels-adjacent `AXScrollArea`) and only when active copy confirms the selected text.
- `TextReplacementPolicy`: replacement planning and post-replacement bookkeeping for selected text, last-word conversion, terminal-tail rewrites, undo/redo replacement methods, selection retention, and direct clipboard-vs-AX selected-text replacement routing.
- `ReplacementFailurePolicy` and `UndoReplacementPolicy`: single failure actions for paste/keyboard/AX replacement failures, including undo-specific cleanup routing, keeping AppDelegate as an executor instead of the owner of cleanup rules.
- `AccessibilitySelectionSearchPolicy` and `AccessibilityReplacementPolicy`: pure AX selection search continuation rules plus verification/timing contract for AX selected-text writes, including empty wrapper/descendant selection handling, silent no-op detection for apps that report AX success without changing the selection, bounded retry behavior for transient focused-application lookup failures, validation of original AX selection ranges, and UTF-16 selection-range planning for reselecting replacement text only when AX supplied a real original range.
- `AccessibilityRolePolicy` and `AccessibilityReplacementCapability`: normalized AX role taxonomy plus typed replacement evidence (`role`, `AXEditable`, `AXSelectedText` settable result/error) for the direct selected-text replacement gate observed in Punto Switcher search/click exception data. The role policy also carries the observed Punto Switcher searchbar/click exception matrix from `default-conf.json` as testable native data, treats `AXScrollArea` as non-editable content based on the observed Mail/Parallels replacement path, and does not recreate proprietary search UI.
- `ConversionSession` and `ConversionOriginPolicy`: first-class undo window, last-conversion state, and explicit redo-origin transitions, scoped to the active application context. Manual layout undo records a manual redo origin, while auto-correction redo keeps its own non-learning origin so repeated hotkey undo/redo does not accidentally inherit layout-conversion or rule-learning behavior.
- `ApplicationBundleIDPolicy`: shared bundle-id normalization for undo context, app context, disabled-app rules, per-app layout memory, browser accessibility setup, and reset-on-return matching.
- `ApplicationContextPolicy`: reset policy for app activation boundaries so typed buffers and undo records do not leak between applications, while Punto's own settings/menu window does not destroy the last external context.
- `ApplicationLayoutMemory`: per-application remembered input layout storage.
- `ApplicationLayoutPolicy`: activation-time layout-memory guard so a newly frontmost TIS layout is not recorded under the previous application id, disabled-app rules cannot trigger automatic layout restore, and an already-active remembered layout does not cause a redundant TIS switch or input-source grace window.
- `KeyboardLayoutVariantPolicy`, `KeyboardLayoutTypePolicy`, `InputSourceLanguagePolicy`, and `InputSourceSelectionPolicy`: EN/RU TIS layout detection from source id/language tags plus selectable-catalog selection that keeps English and Russian sources distinct. Variant classification mirrors the Punto Switcher `isAppleLayout` / `isDvorak` boundary with token-safe checks for default ABC/US English, Dvorak, Apple Russian, and Windows `RussianWin`. The policy layer also preserves the observed `windowsLayoutUsed`, `fixString:isEnglish:isApple:`, `createMacToPcMappingWithString:pcLayoutA:pcLayoutB:`, and `convertStringLayout:withMode:isPCLayout:` selector boundary as tests/audit evidence. `LayoutConverter` now accepts the selected Russian layout type for manual conversion: compatibility calls keep the historical Windows/PC punctuation table, while the Mac path uses observed TIS/UCKeyTranslate output for `com.apple.keylayout.Russian`; `WordTracker` receives the same selected layout type from `AppDelegate`, so last-word and typed-tail capture do not discard Mac-layout physical punctuation before conversion or after conversion/undo/auto-correction/toggle-case tail rewrites. Private Punto Switcher fixString tables remain unguessed beyond public macOS layout evidence. The English side prefers enabled/selectable ABC or US over English variants such as Dvorak, while still letting explicit `englishLayoutID` win. The Russian side includes Punto Switcher-style `kbdLayoutType` support: Mac layout is default, the observed `appl` value maps to Mac, Windows/PC layout prefers `com.apple.keylayout.RussianWin` when installed, and falls back to the normal Russian layout when it is not available. Punto Switcher-style `englishLayoutID` / `russianLayoutID` preferences are mirrored as explicit preferred source IDs that are honored only when they still point at selectable, enabled, matching EN/RU sources; the observed `UNDEFINED` sentinel is normalized to no explicit preference and mirrored on unset legacy writes. Missing required EN/RU layouts surface through a tested `promptUserToInstallLayouts`-shaped diagnostic instead of being treated as an ordinary no-op.
- `InputSourceChangePolicy`: pure guard for keyboard-layout notifications, separating programmatic-switch grace windows, in-flight conversions, and user layout changes that should clear text/undo state.
- `InputSourceSwitchVerificationPolicy`: Punto Switcher-style post-`TISSelectInputSource` verification. A zero OSStatus is accepted only when the current TIS layout id matches the requested target; stale current-layout evidence is treated as a failed switch rather than a successful conversion side effect.
- `LayoutSwitchPolicy`: Punto Switcher-style post-conversion input-source switch gate. It preserves the global switch-after-conversion setting while allowing selected-text conversions to opt out separately from last-word conversion and undo.
- `ConversionProtectionPolicy`: tested orchestration timing contract for startup permission alert delay, programmatic input-source switch grace, and the replacement window action that suppresses hotkey/AX recapture while text is being changed.
- `TextActionPreflightPolicy`: shared preflight for manual text actions, covering global enablement, the native `manualConversionDisabled` setting and Punto Switcher `isManualConversionDisabled` / `setIsManualConversionDisabled:` alias surface, in-flight replacement suppression, disabled applications, secure input, and password-field blocking.
- `SecureInputDiagnosticsPolicy`: Punto Switcher-style diagnostic boundary for secure input. When secure/password context clears tracked text and undo state during key tracking, auto-correction, or manual text actions, the app writes `/tmp/punto.SecureInput.plist` with normalized `SecureInputState`, `Context`, `currentApp`, `runningApps`, and `enabledLayouts` fields for troubleshooting without changing conversion behavior. `Context` distinguishes `secure input` from `password field`, with secure input taking priority when both are true.
- `AccessibilityNotificationPolicy`: pure reset contract for AX focus/main-window/window-created notifications, including own-app and replacement-window suppression. `AXSelectedTextChanged` and the Punto Switcher-observed `AXValueChanged` are still observed for parity/diagnostics, but they are deliberately non-clearing because live text surfaces can emit them for every character and would otherwise erase the raw typed buffer before manual conversion.
- `PasteboardSnapshot`: full pasteboard item/type capture and restore used around Cmd+C/Cmd+V fallbacks and diagnostics.
- `restorePasteboardAfterConversion`: native setting with the Punto Switcher-observed `shouldRestorePasteboard` alias. It defaults on and gates pasteboard restoration for Cmd+C capture fallback, selected-text clipboard replacement, and keyboard-tail paste replacement. `ClipboardReplacementPolicy` pins the observed pasteboard state/timer/string selector surface (`previousPasteboardContents`, `pasteboardRestoreTimer`, `getPasteboardString`, `setPasteboardString:`, and the two restore timer selectors) while keeping the native full-item `PasteboardSnapshot` as the implementation.
- `ClipboardCapturePolicy`: Cmd+C fallback guard and timing contract: copy key code, key-up delay, clipboard polling interval/attempt limit, HID retry point, stale-clipboard rejection, and unchanged-but-matching clipboard acceptance.
- `KeyboardEventTimingPolicy`: shared CGEvent timing contract for selection settling and command key-up spacing. Destructive select-copy verification is intentionally kept out of the production adapter.
- `KeyboardFocusPolicy`: typed AX focus evidence gate for keyboard-tail replacement. It requires a focused application and focused element, rejects disabled elements and known non-editable AX content/control roles, and does not trust unreliable `AXFocused=false` flags from terminal-like surfaces as a hard block.
- `SelectedTextClipboardReplacementPolicy`: clipboard replacement contract for selected text: post-paste delay, optional reselection only for non-empty replacement text, and async clipboard restore only while Punto's replacement remains current.
- `KeyboardReplacementPolicy`: pure guard and timing constants for keyboard-tail replacement: positive delete length, complete backspace sequence, paste delay, and async clipboard restore only if the replacement clipboard item is still current.
- `ClipboardReplacementPolicy`: shared clipboard restore invariant for all paste-based replacement paths so browser selected-text fallback and terminal/last-word keyboard replacement do not diverge.
- `KeyboardEventKeyCodePolicy`: canonical CGEvent key-code table for Cmd+C, Cmd+V, Backspace, and Shift+Left replacement mechanics.
- `AccessibilityApplicationPolicy`: browser application policy derived from Punto Switcher's `default-conf.json` accessibility groups. It keeps the observed browser `inject` bundle-id list separate from the `eui` list, and the app adapter attempts `AXEnhancedUserInterface` only for the observed `eui` bundle ids: Chrome/Chromium, Opera, Firefox, and Yandex Browser. Safari remains in the observed injection list but is not treated as an EUI target.
- `AccessibilityValueBridge`: app-side CoreFoundation bridge for AX values. It keeps concrete `AXUIElement` reads, focused-app/focused-element lookups with optional `AXError` preservation, AX element/element-array traversal attributes, scalar AX string/bool attributes, and `AXValue`/`CFRange` selected-range reads next to the Accessibility adapter so `TextAccessor` does not open-code unsafe AX casts.
- `SoundFeedbackPolicy`: Punto Switcher-style feedback event mapping (`replace`, `reverse`, `misprint`, `switch`, `en`, `ru`, `typeeng`, `typerus`) with a global enable flag that defaults off, per-resource enable state, a legacy `enabledSounds` bitmask bridge in bundled resource order, observed `isSoundOn` / `setSoundState:isSoundOn:` global sound boundary, observed `useSound...` per-event legacy toggle aliases, input-source switch sound context, the observed `shouldSkipNextLanguageChangeSound` suppression shape, and a tested required-resource manifest. Audio files are independently generated short PCM WAV resources under `Resources/Sounds`; no proprietary Punto Switcher audio is copied.
- `StatusIconPolicy`: Punto Switcher-style menu bar state split derived from the observed `icon_active`, `icon_inactive`, and `icon_disabled` resources plus the `updateMenubarIcon:` selector boundary. Native Punto keeps its own template artwork, but the app now distinguishes active, globally inactive, and current-app-disabled states through status-item tint and tooltip updates.
- `LogRetentionPolicy`: Punto Switcher-style bounded file logging shape derived from the observed CocoaLumberjack `DDFileLogger` / `DDFileLogManagerDefault` symbols. The app still writes the script-compatible active log at `/tmp/punto.log`, while oversized logs are archived and pruned by maximum archive count and disk quota.
- `AutoCorrectionEngine`: deterministic user-rule trigger engine for typed word completion.
- `AutoCorrectionPreflightPolicy`: route/security gate for completed-token auto-correction, including token consumption when Punto is disabled, auto-correction is disabled, Enter/Tab-triggered correction is disabled, conversion is in progress, or the current app is disabled. The global auto-correction setting defaults off to match the observed Punto Switcher `isAutocorrectionActive = 0` plist state, while a persisted user setting still wins.
- `UndoLearningSettingsPolicy`: Punto Switcher-style nested `undoLearning` settings boundary for `undoCollectionEnabled`, `mustShowUndoWindow`, and `undoDictionary`, defaulting to the observed plist shape (`false`, `true`, empty dictionary) and normalizing imported dictionary entries. The policy also pins the observed setter, undo-window controller/delegate/resource, checkbox, and undo-state strings (`setUndoCollectionEnabled:`, `setMustShowUndoWindow:`, `setUndoDictionary:`, `UndoWindowController`, `UndoWindowDelegate`, `UndoWindow`, `PMUserRuleUndoAlertFormat`, `showUndoLearningWindowCheckboxChanged:`, `undoLearningCheckboxChanged:`, `undoTries`, `undoPersists`, `undoWasDone`, `undoConvertion`, `resetUndoBuffer`) as compatibility surface without recreating Punto Switcher's proprietary popup UI.
- `AutoCorrectionUndoLearningPolicy`: Punto Switcher-style undo-learning core. It is gated by a native setting that defaults off like the observed `undoLearning.undoCollectionEnabled = 0`, reads that nested legacy field as a fallback through the typed settings policy, mirrors writes back into the full `undoLearning` dictionary, and when enabled removes only the exact auto-correction rule that produced the undone replacement.
- `AutoCorrectionCancellingKeyPolicy`: Punto Switcher-style `cancellingKeys` setting boundary. The native supported/default names are `backspace`, `delete`, `leftArrow`, `rightArrow`, `upArrow`, and `downArrow`; persisted names are normalized and unknown names are dropped. The policy also accepts Punto Switcher's observed `dontAutoconvertWordWithBackspace`, `dontAutoconvertWordWithDelete`, and arrow-key names as aliases for imported settings, including the selector-shaped `dontAutoconvertWordWith...:` strings found in the binary. The observed legacy `cancellingKeys = 0` value is treated as an empty enabled-key mask, while non-zero legacy bit order remains intentionally unmapped until it can be proven. Backspace can suppress auto-correction for an edited token without hardcoding the preference into `WordTracker`, while Delete/navigation keys are represented in the same mask and continue to clear typed state before any stale auto-correction can be formed.
- `AutoCorrectionRuleStore`: JSON and delimited-text import/export boundary for independently authored rules. It intentionally does not copy Punto Switcher dictionary resources.
- `AutoCorrectionRuleSourcePolicy`: native rule-source policy for Punto Switcher's `switcher.use_old_rules` / `switcherUseOldRules` signal: use independently authored starter rules until the user saves rules, preserve an intentionally empty saved list, and fall back to starter rules for unreadable persisted data. The observed old-rules flag defaults on; if an imported plist explicitly disables it before native rules are saved, Punto skips the starter catalog while still accepting imported user rules.
- `LegacyUserRulePolicy`: compatibility import/export for Punto Switcher `userRulesDictionary`, accepting only active non-regexp replacement rules with the observed `rule_string`/`rule`/`is_active`/`do_replace`/`is_regexp` shape. These legacy rules are layered onto the starter catalog only when native rules have not been saved; empty legacy arrays do not suppress starter rules. Native rule edits mirror normalized rules back to the same observed dictionary shape and preserve the create/modify/remove/word-added selector boundary without copying proprietary dictionaries or popup UI.
- `AutoCorrectionStarterCatalog`: independently authored starter rules for common wrong-layout words and English typos. It is a small native seed, not imported from Punto Switcher `ps.dat` or `triggers.dat`.
- `ProductStatisticsPolicy`: local Punto Switcher-style counter semantics for typed words, typed symbols, automatic switches, manual switches, and reverts. It normalizes stale persisted snapshots, reads/writes the observed nested `PSDayuseSettings` keys (`TypedWords`, `TypedSymbols`, `AutoSwitches`, `ManualSwitches`, `Reverts`, `LastDayuseDate`, `LastProductStatDate`) and individual native-compatible counter keys alongside the native snapshot, accepts numeric and string-backed counter imports, merges partially present legacy individual counters with `PSDayuseSettings` field-by-field during import, increments counters only from successful native events, counts completed tokens even when a `reset_on_return` app consumes the token before auto-correction, and pins the observed `PSDayuseStat`, setter/accessor, `product.typed.*`, and `product.switch.*` metric strings in policy/tests/audit while intentionally keeping network reporting out of scope.
- `SettingsPersistencePolicy`: canonical persistence boundary for settings defaults and snapshots whose keys are app identities or app-context tokens, including disabled-app ids, reset-on-return bundle components, per-app remembered layout ids, string/number/bool-backed boolean imports, normal legacy aliases, and inverted legacy aliases.
- Settings can carry Punto Switcher-style aliases when the observed plist uses a different key. The global `isEnabled` flag keeps the observed key and pins `setEnabled:`. `isFirstLaunch` reads `isFirstInstallation`, `launchAtLogin` reads `launchesOnStartup` and pins `setLaunchesOnStartup:`, `showAdvancedSettings` mirrors the observed native-compatible advanced-preferences flag and pins `setShowAdvancedSettings:`, `autoCorrectionEnabled` reads and pins `isAutocorrectionActive`, `autoCorrectionStarterRulesEnabled` reads `switcher.use_old_rules` / `switcherUseOldRules`, `soundEffectsEnabled` reads `isSoundOn`, `enabledSoundResourceNames` reads `enabledSounds` and the observed `useSound...` toggles, `restorePasteboardAfterConversion` reads `shouldRestorePasteboard`, `russianKeyboardLayoutType` reads `kbdLayoutType`, `preferredEnglishInputSourceID` reads `englishLayoutID`, `preferredRussianInputSourceID` reads `russianLayoutID`, `rememberInputSourceForEachApp` reads `shouldRememberInputSourceForEachApp`, `resetOnReturnBundleComponents` reads `switcher.reset_on_return`, and `completelyDisableInExceptionApplications` reads `CompletelyDisableInExceptionApps`. `autoCorrectOnEnterAndTab` reads inverted `shouldNotAutoconvertWithTabOrEnter` and pins `setDontAutoconvertWithEnterOrTab:`, while `suppressAutoCorrectionAfterManualConversion` reads inverted `shouldNotAutoconvertAfterConvertion`. Alias-sensitive boolean getters parse Bool, NSNumber, and common string forms such as `yes`, `0`, `true`, and `off`; they check persistent values, not registered defaults, so fresh native defaults do not mask an imported Punto Switcher plist. All writes mirror native and legacy keys while preserving the native key as the source of truth once explicitly stored.
- `ApplicationDisablePolicy`: native disabled-app rules equivalent to Punto Switcher application exceptions, including current-app toggle actions, status-menu state, state-clear decisions when an app is newly disabled, a `disabledApps` / `setDisabledApplications:` legacy persistence alias, the observed disabled-app preferences-controller strings, and the `CompletelyDisableInExceptionApps` distinction between partial exceptions and full manual-action blocking.
- `ApplicationBundleIDPolicy`: shared bundle-id normalization plus observed volatile system contexts. `com.apple.ScreenSaver.Engine` is treated as volatile for per-app layout memory so lock/screen-saver transitions clear stale text state without creating remembered-layout records for the screen saver process.

The macOS app target wires these policies into:

- `TextAccessor`: Accessibility, clipboard, and CGEvent adapter.
- `InputSourceManager`: TIS input source discovery, current layout id, and switching. It refreshes cached EN/RU sources from the current selectable and enabled catalog through `InputSourceSelectionPolicy` instead of keeping stale source handles across refreshes, reselects the preferred English/Russian source when explicit source IDs, source enabled state, or the Mac/Windows Russian layout setting change, and verifies the current layout id after each `TISSelectInputSource` call before reporting success.
- `AppDelegate`: orchestration only: security checks, disabled-app gates, conversion flow, app activation/layout-memory events.
- `HotkeyManager`: CGEvent adapter over `ModifierOnlyHotkeyStateMachine` and `KeyDownEventPolicy`.

## Current Conversion Flow

1. `HotkeyManager` feeds `flagsChanged` press/release snapshots into `ModifierOnlyHotkeyStateMachine`, which detects `Cmd+Opt+Shift` with debounce and keyDown cancellation. System tap-disabled events are routed through `EventTapLifecyclePolicy` and re-enable the CGEvent tap before returning the event. `keyDown` events are routed through `KeyDownEventPolicy`, including selected-text Yandex search shortcuts.
2. Pointer down events are routed through `PointerEventPolicy` and clear `WordTracker` plus `ConversionSession`, preventing stale typed tails after clicks or cursor moves.
3. AX focus, focused-window, main-window, and window-created notifications from the active app are routed through `AccessibilityNotificationPolicy`; they clear typed text and undo state unless Punto is inside its own short replacement grace window. Selected-text and value-change notifications are subscribed for parity/diagnostics but do not clear typed state.
4. `AppDelegate.handleConvertLayout()` blocks disabled/security/password cases plus the Punto Switcher-style manual-conversion-disabled setting. This setting applies to layout conversion only; it does not globally disable tracking, auto-correction, or toggle-case.
5. `WordTracker` provides `lastTrackedWord` and `lastTrackedTail`.
6. `TextAccessor.captureSelectedText(...)` gathers AX/clipboard observations and passes them into `TextCapturePolicy.captureDecision(...)`, which chooses the replacement strategy:
   - editable AX selection -> AX replacement;
   - non-settable terminal-like selection -> rewrite tracked typed tail, including prompt-prefixed AX selections that end with that typed tail;
   - passive clipboard tail -> keyboard backspace + paste;
   - no safe evidence -> block.
7. `LayoutConverter.convertWithResult(...)` converts text and returns target layout.
8. Mixed or unknown non-convertible results are skipped before any replacement is attempted.
9. `TextAccessor.replaceCapturedText(...)` applies the replacement and returns whether it actually sent a viable replacement path.
10. `TextReplacementPolicy` derives any tracked-tail update, selection-retention behavior, and undo replacement method from the actual successful replacement. Stale last-word tails are rejected instead of being rewritten blindly.
11. `ConversionSession` records the conversion for the 3 second undo window only after replacement reports success, and stores the active app context id with the record.
12. `Cmd+Opt+Delete` mirrors Punto Switcher's cancel-layout-change shortcut by invoking the same scoped undo helper that repeat-convert uses, so explicit cancellation and repeat-hotkey undo share replacement planning, input-source restoration, sound feedback, and the gated auto-correction undo-learning path.
12. `AppDelegate` optionally switches keyboard layout.
    Selected-text conversions pass through a separate selected-text switch gate, matching Punto Switcher's observed `switchLayoutOnSelectedTextSwitch` / `setSwitchLanguageWhenChangingSelectionLayout:` setting shape. Native settings read that legacy key as a fallback and mirror writes back to it.

## Current Auto-Correction Flow

1. `HotkeyManager` forwards ordinary key presses to `WordTracker`.
2. `SoundFeedbackPolicy` may emit typed EN/RU feedback for actual text input after disabled/security/password routing has allowed tracking.
3. `WordTracker` emits a one-shot completed token when a word is followed by Space, Return, Enter, Tab, or a configured hard separator.
4. `ApplicationReturnKeyPolicy` mirrors Punto Switcher's configurable `reset_on_return` bundle-token list. The native default is `telegram`; persisted settings override the token set, including an intentionally empty list, and the observed `switcher.reset_on_return` alias is accepted as a fallback and mirrored on write. Matching is by normalized bundle-id component, so glued suffixes such as `nottelegram` are not reset.
5. `AppDelegate.handleAutoCorrectionIfNeeded()` consumes the completed token and routes disabled/security/password/cancelled-token decisions through `AutoCorrectionPreflightPolicy`, clearing text/undo state when secure input is detected. A Punto Switcher-style setting can suppress auto-correction when the completed-token separator is Return/Enter/Tab while leaving Space-triggered corrections active. Backspace-edited token suppression is driven by the native cancelling-key mask, matching the observed `dontAutoconvertWordWithBackspace` / `cancellingKeys` shape while preserving the buffer for manual conversion; Delete and arrow cancelling keys map through the same policy and keep their stale-state clearing behavior. Manual layout conversion can also mark the rewritten tracked token as suppressed for the next completion, mirroring the observed inverted `shouldNotAutoconvertAfterConvertion` setting and `dontAutoconvertWordAfterConvertion:` selector without applying that suppression to toggle-case or undo flows.
6. `AutoCorrectionEngine` checks `SettingsManager.autoCorrectionRules`.
7. If a rule matches, `TextAccessor.replaceRecentText(...)` deletes `word + separator` and pastes `replacement + separator`.
8. `TextReplacementPolicy.trackedTailAfterRecentTextReplacement(...)` rewrites the tracked tail when it matches the completed token, or discards stale tail context and keeps only the replacement token.
9. `ConversionSession` records the auto-correction in the active app context so the existing short undo path can revert it without crossing application boundaries. Undoing an auto-correction records an auto-correction redo origin, not a generic layout redo, so repeated hotkey toggles do not switch input sources. When undo learning is enabled, that undo can also remove the exact native rule that caused the correction.
10. `Cmd+Opt+A` mirrors Punto Switcher's auto-correction toggle shortcut: `HotkeyManager` consumes the configured hotkey, flips `SettingsManager.autoCorrectionEnabled`, and clears typed/undo state so stale pre-toggle tokens cannot be corrected under the new mode.

## Current Toggle-Case Flow

1. `HotkeyManager` routes `Cmd+Opt+Z` through `KeyDownEventPolicy`.
2. `AppDelegate.handleToggleCase()` blocks disabled/security/password cases and enters the same short protected replacement window as conversion.
3. `TextAccessor.captureSelectedText(...)` uses the same AX/clipboard/terminal-tail decision matrix as layout conversion.
4. `ToggleCasePolicy` builds the toggled text, terminal-tail update, and undo replacement method.
5. `TextAccessor.replaceCapturedText(...)` applies the same safe replacement method selected by the capture policy.
6. Terminal tail rewrites update `WordTracker` so subsequent conversions still have current typed-tail context.
7. `ConversionSession` records the toggle so the existing repeat-convert undo path can revert it inside the active app context.

## Current Application Context Flow

1. `AppDelegate` tracks the active external bundle id from `NSWorkspace.didActivateApplicationNotification`.
2. `ApplicationContextPolicy.shouldResetTextState(...)` decides whether the transition is a real external app switch.
3. Real external app switches clear both `WordTracker` and `ConversionSession` so typed tails and undo records cannot be applied in a different app.
4. Activating Punto's own settings/menu window preserves the last external app context so opening preferences does not destroy the current workflow.
5. `ConversionSession.undoCandidate(contextID:)` only returns records whose stored context id matches the current active app.
6. `ApplicationLayoutPolicy` prevents `didActivateApplication` from writing the newly active TIS layout into the previous app's memory slot; layout restore uses only the new external bundle id, is skipped for disabled applications, and avoids a redundant TIS switch when the remembered layout is already active.

## Current Input Source Flow

1. Programmatic layout switches set a short `ignoreInputSourceChangesUntil` window before calling TIS.
2. `InputSourceChangePolicy` ignores notifications inside that window and keeps the grace deadline alive until it expires.
3. After the grace window expires, in-flight conversion notifications are ignored without clearing text/undo state.
4. Ordinary user layout changes remember the active app's current layout when per-app memory is enabled, then clear `WordTracker` and `ConversionSession`.

## Auto-Correction Rule Formats

Rules are stored as JSON-encoded `AutoCorrectionRule` values in `UserDefaults`; persisted rules are normalized through `AutoCorrectionRuleStore` on read and write so stale snapshots cannot keep blank rules or duplicate triggers alive.
`AutoCorrectionRuleSourcePolicy` selects the effective rules: if the user has never saved rules, Settings returns `AutoCorrectionStarterCatalog.rules`; once rules are saved, even an intentionally empty list stays empty; unreadable persisted payloads fall back to the starter catalog.
The Settings window can import and export user rules. Import accepts:

- JSON arrays of `AutoCorrectionRule`.
- Plain text lines in `trigger<TAB>replacement` format.
- Optional columns: `matchMode` (`exact` or `caseInsensitive`) and `preserveCase` (`true`/`false`).
- `#` and `//` comment lines are ignored; malformed rows are skipped and reported.

Duplicate rules are normalized by `(matchMode, trigger)`, with trimmed triggers lowercased only for `caseInsensitive` rules; later imports override earlier entries.
Export writes the normalized effective rule set as JSON so user-authored rules can be backed up or moved without relying on private Punto Switcher dictionaries.

## Risk Hotspots

- `TextAccessor` still owns AX discovery, CGEvent posting, clipboard capture, paste mechanics, and backspace rewriting. It preserves clipboard state with `PuntoCore.PasteboardSnapshot` around Cmd+C/Cmd+V fallbacks. The capture decision matrix, active clipboard routing after non-settable AX observations, typed selected-text replacement transport, and blocked-capture state cleanup now live in `TextCapturePolicy`; replacement planning, direct clipboard-vs-AX selected-text routing, terminal-tail rewrite bookkeeping, undo/redo method derivation, and clipboard-paired selected-text routing live in `TextReplacementPolicy`; failed replacement cleanup lives in `ReplacementFailurePolicy`; shared replacement clipboard restore invariants live in `ClipboardReplacementPolicy`; Cmd+C fallback timing/stale-result guards live in `ClipboardCapturePolicy`; low-level CGEvent key codes and spacing live in `KeyboardEventKeyCodePolicy` and `KeyboardEventTimingPolicy`; keyboard focus evidence lives in `KeyboardFocusPolicy`; selected-text clipboard replacement guards/timings live in `SelectedTextClipboardReplacementPolicy`; keyboard-tail replacement guards/timings live in `KeyboardReplacementPolicy`; AX selected-text search continuation, empty-probe aggregation, success verification, retry timing, original range validation, and replacement reselection range planning are isolated in `AccessibilitySelectionSearchPolicy` and `AccessibilityReplacementPolicy`; AX value type bridging lives in `AccessibilityValueBridge`; and AX replacement capability evidence is represented by `AccessibilityReplacementCapability`, so terminal fallback ordering, clipboard-copy retry behavior, keyboard replacement preconditions, clipboard restore guards, transient AX lookup failures, empty AX wrapper/descendant selections, blocked unsafe selections, silent AX no-ops, AX range retention, malformed AX range handling, AX value type mismatches, and optimistic/static AX role contradictions are covered or explicitly bounded.
- Browser AX setup is guarded by `AccessibilityApplicationPolicy` and attempts `AXEnhancedUserInterface` for the browser bundle ids observed in Punto Switcher's `eui` accessibility group; actual replacement still requires live AX capability/clipboard evidence.
- Sound feedback is split between `SoundFeedbackPolicy` and app-side `SoundFeedbackController`; bundled independent WAV resources live under `Contents/Resources/Sounds`, missing sounds are logged once and do not affect conversion behavior. Typed EN/RU feedback is emitted only after key tracking passes disabled/security/password gates, input-source switch sounds are suppressed when the switch is caused by text replacement or remembered per-application layout restore to avoid stacked conversion/app-activation + layout sounds, and the global sound setting is exposed in both the menu bar and Settings. Settings also exposes Punto Switcher-style per-resource sound toggles backed by normalized resource names plus the legacy numeric `enabledSounds` bitmask and observed `useSound...` aliases, so individual events can be disabled while the global sound system remains on.
- Editable AX replacement is applied to the actual AX element that produced the selection, not a freshly queried focused element. The cached element is cleared on clipboard, blocked, non-selection, or AX-failure paths to avoid stale replacement targets.
- `AppDelegate` still owns orchestration flags (`ignoreInputSourceChangesUntil`, `isConversionInProgress`), but manual text-action preflight lives in `TextActionPreflightPolicy`, replacement-window timing/action lives in `ConversionProtectionPolicy`, undo state is in `ConversionSession`, redo-origin transitions live in `ConversionOriginPolicy`, and app-switch reset decisions are isolated in `ApplicationContextPolicy`.
- Input-source notification decisions are isolated in `InputSourceChangePolicy`, text layout detection is isolated in `LayoutDetectionPolicy`, typed-word boundaries are isolated in `WordBoundaryPolicy`, and layout language/source selection is isolated in `KeyboardLayoutVariantPolicy`, `KeyboardLayoutTypePolicy`, `InputSourceLanguagePolicy`, and `InputSourceSelectionPolicy`, so programmatic TIS switch noise, real user layout changes, locale language tags, known EN/RU layout ids, selectable-catalog refreshes, default English vs variant selection, Dvorak detection, preferred Russian Mac/Windows layout selection, layout-aware typed punctuation, distinct EN/RU source selection, mixed-layout thresholds, combining grapheme clusters, control characters, and non-EN/RU Unicode are covered by core tests.
- Modifier-only hotkey state, persisted hotkey validation, event-tap lifecycle, keyDown routing, and raw-buffer special-key handling are no longer open-coded in app adapters; invalid persisted shortcuts fall back to defaults, active event handling reads the current settings, menu-bar shortcut labels refresh from settings when the menu opens, and debounce, cancellation, tap re-enable decisions, key-based hotkeys, paste/undo clearing, Backspace, Return/Enter/Tab, Escape, navigation, and ordinary key tracking are covered by `PuntoCoreTest`. `HotkeyManager` routes already-classified shortcut clears through the direct clear callback, so Cmd+C/V/Z/X/A and modified navigation/deletion invalidate typed state and undo without being reinterpreted as ordinary key input. Punto Switcher-style auto-correction toggling and cancel-layout-change are also routed as first-class key-based hotkeys instead of generic modified shortcuts.
- Pointer click invalidation is isolated in `PointerEventPolicy`; `HotkeyManager` listens to mouse-down events only to clear typed state and does not consume the click.
- AX focus/selection invalidation is isolated in `AccessibilityNotificationPolicy` and wired by `AccessibilityStateObserver` against the active app. It observes focus/window/main-window/window-created/selection/value changes; value and selected-text mutations are non-clearing diagnostics, so normal typing does not erase the raw typed buffer.
- Toggle-case behavior is now in `CaseConverter` and `ToggleCasePolicy`; it uses the same capture/replacement policy as conversion, records undo, and covers mixed-case reversibility plus terminal tail capture in `PuntoCoreTest`.
- Terminal-like support is capability-based, and the pure decision pieces are now in `TextCapturePolicy`; AX role taxonomy plus typed direct-replacement capability evidence live in `AccessibilityRolePolicy`, while concrete AX traversal and paste mechanics still live in `TextAccessor`.
- AX traversal bounds live in `AccessibilityTraversalPolicy`: selected-text descendant search, password-field descendant checks, and AXWebArea ancestor-role collection share explicit tested limits instead of hardcoded recursion depths.
- Password-field blocking checks the focused AX element, app `focusedUIElement`, and descendants up to the same bounded depth used for selection discovery. The role/subrole decision is covered by `TextTrackingSecurityPolicy` using the same AX role normalization as `AccessibilityRolePolicy`.
- Prompt-prefixed terminal selections are accepted only when the trimmed AX selection ends with the exact tracked typed tail and the prompt marker is the final non-whitespace character before that tail. Partial terminal selections and terminal-tail rewrites share `WordBoundaryPolicy.hasCommandSuffixBoundary(...)`, so a suffix is accepted only when it starts at the same command boundary in both capture and replacement; prefix, middle, and partial-word suffix selections are blocked. Passive clipboard terminal selections remain stricter: they must equal the tracked typed tail exactly.
- Last-word and auto-correction tracked-tail updates use the same suffix-boundary guard, so a stale/glued tail like `otherghbdtn` cannot be rewritten as if `ghbdtn` were the current word.
- Production `WordTracker` keeps a larger typed-tail buffer than the compact last-word buffer, so terminal command-tail validation can cover longer commands without making ordinary last-word conversion stale.
- `PuntoTest` remains copy-heavy. It can catch scenario drift, but it cannot prove production classes still behave the same. High-value cases should keep moving into `PuntoCoreTest`; dash-suffix auto-correction and mapped-punctuation boundaries now exercise production `WordBoundaryPolicy`, `WordTracker`, and `AutoCorrectionReplacementPolicy` directly.
- Per-app layout memory is default-off, exposed in Settings, and persisted through `SettingsManager`. Activation restore is guarded so frontmost-app layout observations cannot corrupt the previous app's remembered layout. Settings also exposes the remembered layout snapshot so stale per-app records can be inspected, removed, or cleared.
- The observed screen saver engine bundle id is classified as a volatile system context for layout memory. App-context switching still clears text/undo state, but layout restore and remembered-layout writes are skipped for `com.apple.ScreenSaver.Engine`.
- App context isolation clears typed buffers and undo records on real external app switches, while preserving state when Punto's own window activates.
- Settings defaults, app-identity snapshots, and app-context snapshots are centralized at the persistence boundary, so stale `UserDefaults` values with whitespace, casing drift, blank app ids, blank reset-on-return tokens, or blank layout ids cannot leak into runtime policy or Settings UI. Missing reset-on-return settings use the native default; unreadable payloads fall back to the default; an explicitly saved empty list disables return-key resets for all bundle components. The Settings window exposes this list in the Return Reset Apps editor.
- Auto-correction has the event pipeline, rule engine, independently authored starter catalog, JSON/text import, JSON export, Settings import/export buttons, a Punto Switcher-style Enter/Tab trigger toggle, a Punto Switcher-style cancelling-key mask, a post-manual-conversion suppression toggle, and a native Settings rule editor table with search, validation status, and invalid-row highlighting. Manual conversion can be disabled independently from auto-correction and toggle-case.
- Disabled-app rules can be toggled from the menu bar for the last active app and managed from Settings. The toggle action and status-menu state are isolated in `ApplicationDisablePolicy`, refuse Punto's own bundle id, normalize the external app id, and clear typed/undo state only when the app is newly disabled. By default, disabled-app exceptions suppress tracking and auto-correction while leaving manual conversion/search/toggle hotkeys available; the Punto Switcher-style full-disable setting makes those manual actions pass through too. The Settings editor can add the current app, remove selected apps, and resolve stored bundle IDs back to app names when possible.

## Refactor Direction

Keep app-facing behavior stable and extract testable policies one at a time:

1. Continue shrinking `TextAccessor` by extracting replacement planning and verification policies.
2. Convert high-value scenarios from `PuntoTest` into `PuntoCoreTest` as production-code tests.
3. Add integration scripts only around real macOS surfaces, with explicit preconditions and log assertions.
