# Punto Architecture Overview

## Runtime Boundaries

Punto now has small importable `PuntoCore`, `PuntoSettings`, and `PuntoRuntime` modules plus a macOS app target.

- `PuntoCore`: deterministic logic that can be tested without Accessibility permissions or global event taps.
- `PuntoSettings`: native settings facade, storage adapter, slot registries, and Punto Switcher import fallback resolver.
- `PuntoRuntime`: macOS live transport adapters for event taps, Accessibility, clipboard, keyboard events, selected-text access, and TIS input source switching. It imports `PuntoCore` and `PuntoSettings`, but it does not own app lifecycle or UI.
- `Punto`: macOS app shell: lifecycle, coordinator wiring, status bar, settings UI, and calls into `PuntoRuntime`.
- `PuntoCoreTest`: executable test harness that imports real `PuntoCore` classes. This exists because the installed CLT Swift toolchain currently does not provide `XCTest` or Swift `Testing`.
- `PuntoSettingsTest`: executable test harness over isolated `UserDefaults` suites. It verifies native-over-legacy precedence, read-only import fallbacks, settings notifications, and normalized input-source ids through the real `SettingsManager`.
- `PuntoParityTest`: executable corpus harness over production `PuntoCore`, derived from the documented user-facing conversion, layout-detection, word-tracking, terminal capture, and replacement parity cases.
- Retired `PuntoTest`: the old broad simulation executable was removed after its useful cases moved into production-code harnesses. `PuntoCoreTest`, `PuntoParityTest`, `PuntoDiag`, reverse audit, native bundle audit, and focused macOS harness scripts are the active regression gates.
- `PuntoDiag`: command-line diagnostics that exercise real production modules. `Scripts/debug.sh components` delegates to `PuntoCoreTest` and `PuntoDiag`; it must not carry inline copies of `LayoutConverter`, `WordTracker`, or other core logic.

## Native Punto Switcher Equivalents

The read-only Punto Switcher pass exposed a useful boundary split. Punto now mirrors that split with native Swift types:

- App bundle metadata mirrors Punto Switcher's agent-app shape: the native bundle stays a menu-bar agent and explicitly disables sudden termination so macOS does not opportunistically kill the event-tap process in ways Punto Switcher opted out of. `Scripts/deploy.sh` copies the plist and entitlements before signing so installed metadata stays aligned with source changes.
- `WordTracker`: typed raw word and typed command tail buffer. Terminal capture reads a trimmed tail; auto-correction reads a boundary-preserving tail so `word + separator` can be rewritten without losing prior same-layout context. Completed tokens also carry a native cancellation flag for Punto Switcher-style "do not autoconvert this edited word" behavior.
- `WordTrackingPolicy`: special-key contract for the raw text buffer: Escape/external commands/navigation clear state, Backspace removes one character, Return/Enter/Tab complete a token, and ordinary produced characters continue tracking. `KeyPressRuntimeCoordinator` applies key-tracking preflight, reset-on-return, statistics, typed-text sounds, and auto-correction routing to the live app adapters so `AppDelegate` does not own ordinary key-press runtime policy.
- `KeyboardLayoutMappingPolicy` and `WordBoundaryPolicy`: one native source of truth for QWERTY/Dvorak English output, Windows/PC Russian mappings, and Apple-Russian physical-key mappings plus explicit typed-boundary, command-suffix, and terminal-prompt marker rules shared by `LayoutConverter`, `WordTracker`, terminal capture, terminal-tail replacement, and tests. The mapping policy exposes prebuilt `KeyboardLayoutCharacterMaps` for each English/Russian layout pair, so forward maps, reverse maps, reverse ambiguity fixes, conversion majority checks, and boundary punctuation decisions cannot drift or rebuild per call. It separates true separators such as Space, `=`, shell operators, and brackets from layout-mapped punctuation such as `/`, `?`, `.`, `,`, `;`, quotes, square brackets, mapped shifted-number symbols, and Dvorak punctuation outputs that must stay inside wrong-layout words. Typed word-boundary checks are layout-aware for both live key events and replayed replacement tails: the Mac Russian path keeps Apple-layout physical punctuation such as backslash/pipe and shifted number-row symbols inside the tracked wrong-layout word, the Windows/PC path keeps mapped shifted-number punctuation such as `@`, `#`, `$`, `^`, and `&` without losing the shell-safety boundary for `|`, and the Dvorak path keeps punctuation outputs such as `-` when they correspond to Russian letters.
- `Hotkey`, `HotkeyValidationPolicy`, `HotkeyCollisionPolicy`, `HotkeyRoutingPolicy`, `ModifierOnlyHotkeyStateMachine`, `KeyDownEventPolicy`, `KeyTrackingRuntimePolicy`, and `EventTapLifecyclePolicy`: shortcut defaults/display/serialization, settings-boundary validation for persisted shortcuts, Punto Switcher-style shortcut editor guards for duplicate shortcuts and raw/shortcut character keycode filtering, global enable/app-disable routing plus state cleanup actions and hotkey pass-through/matched log shape, pure press-release/debounce/cancel behavior for modifier-only hotkeys, keyDown routing for key-based convert/toggle-case/toggle-auto-correction/cancel-last-conversion hotkeys, paste/undo tracker clearing, ordinary key tracking runtime for route/security/reset-on-return/undo-clear decisions, and event-tap re-enable decisions after system tap disable events.
- `LegacyHotkeyPolicy`: Punto Switcher shortcut dictionary compatibility for `charKeycode`, `isCommandUsed`, `isAltUsed`, `isShiftUsed`, and `isControlUsed`, including numeric/bool values and string-backed import forms. Native Codable `Hotkey` settings remain the source of truth once present, while legacy `shortcutChangeLayout`, `shortcutChangeCase`, `shortcutSwitchAutocorrection`, `shortcutCancelLayoutChange`, `shortcutFindInYandex`, and `shortcutFindInSlovari` dictionaries are accepted as import fallbacks through `legacy*Key` constants. The observed shortcut keys, setter/controller/field boundary (`setShortcut:`, `shortcutWithDictionary:`, `resetShortcutsToDefaults:`, per-shortcut setters, `shortcutsPreferencesController`, `switchAutocorrection:`, `cancelLayoutChangeShortcut`, `switchAutocorrectionShortcut`, `changeCaseShortcut`, `setChangeCaseShortcut:`, and `ShortcutField`) live in `PuntoSwitcherObservedSurface`; tests align the runtime aliases back to those anchors so settings compatibility cannot drift silently.
- `SearchShortcutPolicy`, `SelectedTextSearchPolicy`, and `ApplicationCommandRuntimeCoordinator`: selected-text search URL building plus route/runtime planning and app-side execution for the Punto Switcher-observed Yandex search and Slovari/translate shortcut path. Search shortcuts are valid as explicit `Not Set` hotkeys by default, can be assigned in settings, capture selected text through the same AX/clipboard safety gate, reject unsafe stale terminal fallbacks, and open the derived URL without modifying text or conversion undo state. Runtime planning keeps blocked-capture cleanup logs, empty-query/no-text logs, URL-open logs, and icon-flash intent out of `AppDelegate`.
- `SearchbarSettingsPolicy` and `SearchClickPolicy`: Punto Switcher-style `PSSearchbarSettings` import compatibility for `ActivationShortcut`, `Autoactivation`, `AutoactivationExceptions`, `AlertShownIn`, `ShouldSearchByDoubleClick`, and `SitesearchPromptCounter`, defaulting to the observed `default-conf.json` values (`true`, `false`, `3`) plus an unset activation shortcut, empty exception list, and the observed initial alert date marker. Click-search policy also pins the observed `canDoSearchClick`, `showSearchWindowAutomatically`, `showSearchWindowSelectedText`, and `setIsClickSearch:` gates and only allows selected-text search after an eligible left double click when both the setting and live AX role capability are true. The event tap performs only cheap click classification, then the app coordinator waits for the double-click selection to settle before checking live AX role capability on the main runtime path and reusing selected-text Yandex search. Pointer clicks still clear typed/undo state immediately. The Settings window exposes the same effective `ShouldSearchByDoubleClick` behavior under advanced settings, but native writes go to `searchSelectedTextByDoubleClick`; `PSSearchbarSettings` is read only as a legacy fallback. The native app does not recreate the proprietary searchbar suggestion UI.
- `ApplicationUpdateSettingsPolicy`: Punto Switcher-style updater/install-state settings boundary for `configVersion`, `isFirstInstallation`, install/update booleans, update-request rate, automatic-check preference, and observed request/shown/statistics dates. It preserves the import plist shape and defaults, pins the observed updater key boundary in tests/audit, and does not own network update checks or product-statistics upload behavior. Runtime writes use the normalized native Codable `applicationUpdateSettings` payload; observed updater keys are read-only import evidence except for one-shot imported presentation-flag consumption, and the legacy dictionary export helper is deliberately absent.
- `StartupPresentationPolicy` and `StartupRuntimeCoordinator`: Punto Switcher-style installer/first-run/welcome/update-presentation gate plus app-side execution. It recognizes the observed `--install` launch argument, marks the app as just installed, exits updating state, treats native first launch, legacy `isFirstInstallation`, and observed `isJustInstalled` as welcome triggers, then consumes the install flags after showing onboarding while preserving unrelated updater settings. Routine first-launch writes stay native-only; only the explicit onboarding-consumption path clears imported `isFirstInstallation` / `isJustInstalled` flags so legacy state cannot reopen welcome repeatedly. It also preserves the observed `showUpdateFinishedTooltip` boundary by consuming `isJustUpdated` / `isUpdating` after a native update-finished presentation log, without implementing Yandex network update checks.
- `AccessibilityPreferencesPolicy`: Punto Switcher-style Accessibility-permission opener and alert-copy boundary. It pins the observed `launchAccessibilityPreferences` / `openAccesibilityPrefPane:` selector surface, opens the observed `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` URL first, keeps the observed `System Preferences` AppleScript reveal-anchor fallback for systems or environments where URL opening fails, and preserves the observed modern/legacy Accessibility alert message keys while using native-owned UI copy. `StartupRuntimeCoordinator` owns the live AX trust prompt, delayed permission alert, System Settings open/fallback, and permission polling timer.
- `PointerEventPolicy`: pointer down events invalidate typed-tail and undo state because a click can move focus/cursor without producing a keyboard event. This mirrors Punto Switcher's click/search awareness without implementing proprietary search suggestions.
- `LayoutConverter`: deterministic layout conversion and target-layout reporting. It resolves one `KeyboardLayoutCharacterMaps` value for the requested layout pair and uses that same value for forward conversion, reverse conversion, and punctuation-only majority decisions, so conversion and typed-word boundary decisions cannot drift through duplicated punctuation tables or ad hoc reverse-map construction.
- `ManualLayoutConversionPolicy`, `ManualLayoutConversionRuntimePolicy`, and `ManualTextActionRuntimeCoordinator`: pure planners plus app-side execution for the manual conversion hotkey. The source policy gives selected text priority, blocks unsafe non-settable selections, converts terminal tails and ordinary selections through the same replacement policy, falls back to last-word conversion only when there is no safe selection, and reports stale last-word tail cleanup separately from ordinary no-op conversions. The runtime policy owns selected-text vs last-word log labels, abort cleanup method, stale-tail clear reason, and the exact `TextReplacementCommitPlan`; the coordinator applies capture, replacement, timing logs, undo-first behavior, and commit side effects so `AppDelegate` stays focused on hotkey/lifecycle wiring.
- `LayoutDetectionPolicy`: shared single-scalar ASCII/Cyrillic letter classification and the strict 80/20 mixed-layout threshold used by conversion and typed-buffer corruption checks. Combining grapheme clusters, emoji/ZWJ sequences, CJK text, and control characters are treated as non-EN/RU evidence so they can pass through conversion without triggering a layout switch by their first Unicode scalar.
- User-facing `convertWithResult` rejects genuinely mixed English/Russian text as non-applicable; the convenience `convert` API delegates to the same safe decision path so diagnostic callers cannot accidentally apply majority conversion to mixed EN/RU text. Punctuation-only unknown text can still convert through the physical-key majority fallback.
- `CaseConverter`: reversible per-character case inversion for `Cmd+Opt+Z` (`Hello` -> `hELLO` -> `Hello`, while digits/punctuation stay unchanged).
- `ToggleCasePolicy`: replacement and undo-record planning for case toggles, using the same selected-text and terminal-tail replacement methods as layout conversion.
- `ToggleCaseConversionPolicy`: pure route and runtime planner for toggle-case execution. It keeps unsafe-capture blocking, no-text, skipped replacement, keep-selection decisions, failure cleanup method, terminal-tail replay, logs, and the exact commit plan inside the manual text-action runtime boundary, matching the manual-conversion planner shape.
- `TextCapturePolicy`: pure policy for terminal/non-settable selection, prompt-prefixed terminal tail extraction, active clipboard fallback routing after non-settable AX observations, passive clipboard tail validation, typed selected-text replacement transport, blocked-capture stale-state cleanup reasons, and the capture decision matrix for AX/clipboard observations. Non-settable content replacement is allowed through clipboard transport only for observed content surfaces (`AXWebArea` and the Mail/Parallels-adjacent `AXScrollArea`) and only when active copy confirms the selected text.
- `TextReplacementPolicy`: replacement planning and post-replacement bookkeeping for selected text, last-word conversion, terminal-tail rewrites, undo/redo replacement methods, selection retention, and direct clipboard-vs-AX selected-text replacement routing.
- `TextReplacementCommitPolicy`: pure commit semantics after a successful text replacement: tracked-tail rewrite reason/suppression, layout-switch target/surface, sound feedback, product statistics, and conversion-record origin for manual selected-text conversion, last-word conversion, toggle-case, and auto-correction. `AppDelegate` remains the side-effect executor instead of owning these per-feature bookkeeping rules.
- `ReplacementFailurePolicy`, `UndoReplacementPolicy`, and `UndoRuntimePolicy`: single failure actions for paste/keyboard/AX replacement failures, undo replacement planning, layout-switch/redo-origin/undo-learning decisions, post-apply undo commit planning, and undo-specific cleanup routing. Replacement, undo replacement, and undo-plan failure actions own their typed/undo cleanup reasons and log strings, keeping AppDelegate as an executor instead of the owner of cleanup rules.
- `AccessibilitySelectionSearchPolicy` and `AccessibilityReplacementPolicy`: pure AX selection search continuation rules plus verification/timing contract for AX selected-text writes, including empty wrapper/descendant selection handling, silent no-op detection for apps that report AX success without changing the selection, bounded retry behavior for transient focused-application lookup failures, validation of original AX selection ranges, and UTF-16 selection-range planning for reselecting replacement text only when AX supplied a real original range.
- `AccessibilityRolePolicy` and `AccessibilityReplacementCapability`: normalized AX role taxonomy plus typed replacement evidence (`role`, `AXEditable`, `AXSelectedText` settable result/error) for the direct selected-text replacement gate observed in Punto Switcher search/click exception data. The role policy also carries the observed Punto Switcher searchbar/click exception matrix from `default-conf.json` as testable native data, pins the observed Mail/Parallels helper surface (`applyMailBehaviour...`, `numberOfDeletionsInMail`, `Mail`, `com.parallels.desktop`, `AXScrollArea`), treats `AXScrollArea` as non-editable content, and does not recreate proprietary search UI.
- `AccessibilityElementClient`: app-side AX focus/role adapter for focused element lookup, app-focused fallback, password-field tree inspection, search-click role checks, AX selected-text replacement capability evidence, ancestor role collection, keyboard-focus evidence, and browser/Electron `AXEnhancedUserInterface` setup. It keeps live AX client plumbing out of `TextAccessor`, while policy modules still own traversal limits, retry timing, role classification, and replacement gates.
- `AccessibilityTextSelectionTransport`: app-side `AXSelectedText` adapter for focused/app-focused/descendant selected-text probing, editable-selection target caching, AX selected-text writes, silent-no-op verification, and replacement reselection. It keeps concrete selected-text AX attributes and `AXValue` range writes out of `TextAccessor`; policies still own search continuation, verification timing, original range validation, and UTF-16 range planning.
- `ConversionSession`, `ConversionOriginPolicy`, `UndoRuntimePolicy`, and `UndoRuntimeCoordinator`: first-class undo window, last-conversion state, executable undo planning/application, and explicit redo-origin transitions, scoped to the active application context. Manual layout undo records a manual redo origin, terminal-tail undo replays the rewritten command tail, and auto-correction redo keeps its own non-learning origin so repeated hotkey undo/redo does not accidentally inherit layout-conversion or rule-learning behavior.
- `ApplicationBundleIDPolicy`: shared bundle-id normalization for undo context, app context, disabled-app rules, per-app layout memory, browser accessibility setup, and reset-on-return matching.
- `ApplicationContextPolicy`: activation runtime policy for app boundaries so typed buffers and undo records do not leak between applications, while Punto's own settings/menu window does not destroy the last external context. It owns the self-activation preservation log and the external-switch cleanup reasons; `ApplicationRuntimeCoordinator` applies app activation, input-source notification, input-source preference refresh, and remembered-layout plans so active external-app context and TIS preference-change cleanup stay out of `AppDelegate`.
- `ApplicationLayoutMemory`: per-application remembered input layout storage.
- `ApplicationLayoutPolicy`: activation-time layout-memory guard so a newly frontmost TIS layout is not recorded under the previous application id, disabled-app rules cannot trigger automatic layout restore, and an already-active remembered layout does not cause a redundant TIS switch or input-source grace window. `ApplicationRuntimeCoordinator` owns the live per-application layout memory snapshot and applies these decisions to `InputSourceManager` and native settings.
- `KeyboardLayoutMappingPolicy`, `KeyboardLayoutVariantPolicy`, `KeyboardLayoutTypePolicy`, `InputSourceLanguagePolicy`, and `InputSourceSelectionPolicy`: EN/RU TIS layout detection from source id/language tags plus selectable-catalog selection that keeps English and Russian sources distinct. Variant classification mirrors the Punto Switcher `isAppleLayout` / `isDvorak` boundary with token-safe checks for default ABC/US English, Dvorak, Apple Russian, and Windows `RussianWin`. The policy layer also preserves the observed `windowsLayoutUsed`, `fixString:isEnglish:isApple:`, `createMacToPcMappingWithString:pcLayoutA:pcLayoutB:`, and `convertStringLayout:withMode:isPCLayout:` selector boundary as tests/audit evidence. `LayoutConverter` now accepts both the effective English layout variant and the selected Russian layout type for manual conversion and gets prebuilt QWERTY, Dvorak, Windows/PC, and Apple-Russian character-map pairs from `KeyboardLayoutMappingPolicy`: compatibility calls keep the historical QWERTY + Windows/PC punctuation table, the Mac path uses observed TIS/UCKeyTranslate output for `com.apple.keylayout.Russian`, and the Dvorak path remaps English output through the physical-key table before applying the Russian map. `WordTracker` receives the same effective English/Russian layout model from runtime, preferring the current active Dvorak source before falling back to the selected or preferred English source, so last-word and typed-tail capture do not discard layout-mapped physical punctuation before conversion or after conversion/undo/auto-correction/toggle-case tail rewrites. Private Punto Switcher fixString tables remain unguessed beyond public macOS layout evidence. The English side prefers enabled/selectable ABC or US over English variants such as Dvorak, while still letting explicit `englishLayoutID` win even if the selectable source is disabled. The Russian side includes Punto Switcher-style `kbdLayoutType` support: Mac layout is default, the observed `appl` value maps to Mac, Windows/PC layout prefers `com.apple.keylayout.RussianWin` when installed or enableable, and falls back to the normal Russian layout when it is not available. Punto Switcher-style `englishLayoutID` / `russianLayoutID` preferences are accepted as explicit preferred source-id import fallbacks; selected disabled sources are returned with a tested enable list so `InputSourceManager` can call `TISEnableInputSource` and log the observed `handleInputSourcesEnabled`, `inputSourceEnabled:`, or failed-enable message shape before falling back to `promptUserToInstallLayouts`. The observed `UNDEFINED` sentinel is normalized to no explicit preference. Runtime writes stay on native input-source keys.
- `InputSourceChangePolicy`: pure guard for keyboard-layout notifications, separating programmatic-switch grace windows, in-flight conversions, and user layout changes that should clear text/undo state.
- `InputSourceSwitchVerificationPolicy`: Punto Switcher-style post-`TISSelectInputSource` verification. A zero OSStatus is accepted only when the current TIS layout id matches the requested target; stale current-layout evidence is treated as a failed switch rather than a successful conversion side effect.
- `LayoutSwitchPolicy` and `LayoutSwitchRuntimePolicy`: Punto Switcher-style post-conversion input-source switch gate plus executable runtime plan. They preserve the global switch-after-conversion setting while allowing selected-text conversions to opt out separately from last-word conversion and undo, derive EN/RU switch requests with the programmatic input-source grace deadline, and make mixed/unknown target cleanup explicit before `TextActionRuntimeCoordinator` calls TIS.
- `ConversionProtectionPolicy`: tested orchestration timing contract for startup permission alert delay, programmatic input-source switch grace, and the replacement window action that suppresses hotkey/AX recapture while text is being changed.
- `TextActionPreflightPolicy` and `TextActionRuntimePreflightPolicy`: shared preflight for manual text actions, covering global enablement, the native `manualConversionDisabled` setting and Punto Switcher `isManualConversionDisabled` / `setIsManualConversionDisabled:` alias surface, in-flight replacement suppression, disabled applications, secure input, and password-field blocking. Runtime composition keeps route checks separate from live secure/password AX probes; `TextActionRuntimeCoordinator` applies the plan to replacement-window state, secure diagnostics, failed-capture cleanup, replacement commits, layout switching, sound, statistics, and undo records.
- `TextTrackingSecurityPolicy` and `SecureInputDiagnosticsPolicy`: Punto Switcher-style secure/password text safety boundary. Security policy owns text tracking gates plus secure/password state cleanup actions, clear reasons, diagnostic context priority, and log strings. When secure/password context clears tracked text and undo state during key tracking, auto-correction, or manual text actions, the app writes `/tmp/punto.SecureInput.plist` with normalized `SecureInputState`, `Context`, `currentApp`, `runningApps`, and `enabledLayouts` fields for troubleshooting without changing conversion behavior. `Context` distinguishes `secure input` from `password field`, with secure input taking priority when both are true.
- `AccessibilityNotificationPolicy`: pure reset contract for AX focus/main-window/window-created notifications, including own-app and replacement-window suppression. `AXSelectedTextChanged` and the Punto Switcher-observed `AXValueChanged` are still observed for parity/diagnostics, but they are deliberately non-clearing because live text surfaces can emit them for every character and would otherwise erase the raw typed buffer before manual conversion.
- Runtime `PasteboardSnapshot`: full pasteboard item/type capture and restore used around Cmd+C/Cmd+V fallbacks and diagnostics. It lives in `PuntoRuntime`, not `PuntoCore`, so core policy code does not carry AppKit pasteboard types.
- `restorePasteboardAfterConversion`: native setting with the Punto Switcher-observed `shouldRestorePasteboard` alias. It defaults on and gates pasteboard restoration for Cmd+C capture fallback, selected-text clipboard replacement, and keyboard-tail paste replacement. `ClipboardReplacementPolicy` pins the observed pasteboard state/timer/string selector surface (`previousPasteboardContents`, `pasteboardRestoreTimer`, `getPasteboardString`, `setPasteboardString:`, and the two restore timer selectors) while keeping the native full-item `PasteboardSnapshot` as the implementation.
- `ClipboardCapturePolicy`: Cmd+C fallback guard and timing contract: copy key code, key-up delay, clipboard polling interval/attempt limit, HID retry point, stale-clipboard rejection, and unchanged-but-matching clipboard acceptance.
- `ClipboardTransport`: app-side NSPasteboard adapter for selected-text capture, passive clipboard reads, selected-text clipboard paste replacement, keyboard-tail paste replacement, full-item snapshot restoration, and async restore guards. It keeps pasteboard mutation and restore boilerplate out of `TextAccessor` and out of `PuntoCore`; policy modules still own stale-copy acceptance, paste delays, and restore invariants.
- `KeyboardEventTimingPolicy`: shared CGEvent timing contract for selection settling and command key-up spacing. Destructive select-copy verification is intentionally kept out of the production adapter.
- `KeyboardEventTransport`: app-side CGEvent poster for Cmd+C, Cmd+V, Shift+Left selection replay, exact Backspace loops, and modifier key-up cleanup. It keeps keyboard event creation out of `TextAccessor`; policy modules still own key codes, delays, and safety gates.
- `KeyboardFocusPolicy`: typed AX focus evidence gate for keyboard-tail replacement. It requires a focused application and focused element, rejects disabled elements and known non-editable AX content/control roles, and does not trust unreliable `AXFocused=false` flags from terminal-like surfaces as a hard block.
- `SelectedTextClipboardReplacementPolicy`: clipboard replacement contract for selected text: post-paste delay, optional reselection only for non-empty replacement text, and async clipboard restore only while Punto's replacement remains current.
- `KeyboardReplacementPolicy`: pure guard and timing constants for keyboard-tail replacement: positive delete length, complete backspace sequence, paste delay, and async clipboard restore only if the replacement clipboard item is still current.
- `ClipboardReplacementPolicy`: shared clipboard restore invariant for all paste-based replacement paths so browser selected-text fallback and terminal/last-word keyboard replacement do not diverge.
- `KeyboardEventKeyCodePolicy`: canonical CGEvent key-code table for Cmd+C, Cmd+V, Backspace, and Shift+Left replacement mechanics.
- `AccessibilityApplicationPolicy`: browser application policy derived from Punto Switcher's `default-conf.json` accessibility groups. It keeps the observed browser `inject` bundle-id list separate from the `eui` list, and the app adapter attempts `AXEnhancedUserInterface` only for the observed `eui` bundle ids: Chrome/Chromium, Opera, Firefox, and Yandex Browser. Safari remains in the observed injection list but is not treated as an EUI target.
- `AccessibilityValueBridge`: app-side CoreFoundation bridge for AX values. It keeps concrete `AXUIElement` reads, focused-app/focused-element lookups with optional `AXError` preservation, AX element/element-array traversal attributes, scalar AX string/bool attributes, and `AXValue`/`CFRange` selected-range reads next to the Accessibility adapter so `TextAccessor` does not open-code unsafe AX casts.
- `SoundFeedbackPolicy`: Punto Switcher-style feedback event mapping (`replace`, `reverse`, `misprint`, `switch`, `en`, `ru`, `typeeng`, `typerus`) with a global enable flag that defaults off, per-resource enable state, import-only legacy `enabledSounds` bitmask parsing in bundled resource order, observed `isSoundOn` / `setSoundState:isSoundOn:` global sound boundary, observed `useSound...` per-event legacy toggle aliases, input-source switch sound context, the observed `shouldSkipNextLanguageChangeSound` suppression shape, and a tested required-resource manifest. Audio files are independently generated short PCM WAV resources under `Resources/Sounds`; no proprietary Punto Switcher audio is copied.
- `StatusIconPolicy`: Punto Switcher-style menu bar state split derived from the observed `icon_active`, `icon_inactive`, and `icon_disabled` resources plus the `updateMenubarIcon:` selector boundary. Native Punto keeps its own template artwork, but the app now distinguishes active, globally inactive, and current-app-disabled states through status-item tint and tooltip updates.
- `LogRetentionPolicy` and `PuntoLog.prepareForNewSession()`: Punto Switcher-style bounded file logging shape derived from the observed CocoaLumberjack `DDFileLogger` / `DDFileLogManagerDefault` symbols. The app still writes the script-compatible active log at `/tmp/punto.log`, but non-empty startup logs and oversized active logs are archived under deterministic Punto-style names, collision-safe suffixes are used when needed, and old archives are pruned by maximum archive count and disk quota.
- `AutoCorrectionEngine`: deterministic user-rule trigger engine for typed word completion.
- `AutoCorrectionPreflightPolicy`: route/security gate for completed-token auto-correction, including token consumption when Punto is disabled, auto-correction is disabled, Enter/Tab-triggered correction is disabled, conversion is in progress, or the current app is disabled. The global auto-correction setting defaults off to match the observed Punto Switcher `isAutocorrectionActive = 0` plist state, while a persisted user setting still wins.
- `AutoCorrectionRuntimePolicy`: app-facing auto-correction decision layer that composes completed-token statistics, route preflight, secure/password gating, rule lookup, replacement planning, replacement logs, failure cleanup, and commit planning into explicit runtime outcomes. The gate phase runs before typed-tail lookup, so secure/password blocks clear state without reading stale tail context; `AutoCorrectionRuntimeCoordinator` owns the live rule engine and applies the plan through `TextAccessor` and `TextActionRuntimeCoordinator`.
- `AutoCorrectionTogglePolicy`: app-facing auto-correction hotkey toggle plan. It owns the new enabled value, typed/undo state cleanup reasons, status flash decision, and log shape so the command runtime only applies the plan.
- `UndoLearningSettingsPolicy`: Punto Switcher-style nested `undoLearning` settings boundary for `undoCollectionEnabled`, `mustShowUndoWindow`, and `undoDictionary`, defaulting to the observed plist shape (`false`, `true`, empty dictionary) and normalizing imported dictionary entries.
- `AutoCorrectionUndoLearningPolicy`: Punto Switcher-style undo-learning core. It is gated by a native setting that defaults off like the observed `undoLearning.undoCollectionEnabled = 0`, reads that nested legacy field as a fallback through the typed settings policy, and when enabled removes only the exact auto-correction rule that produced the undone replacement.
- `AutoCorrectionCancellingKeyPolicy`: Punto Switcher-style `cancellingKeys` setting boundary. The native supported/default names are `backspace`, `delete`, `leftArrow`, `rightArrow`, `upArrow`, and `downArrow`; persisted names are normalized and unknown names are dropped. The policy also accepts Punto Switcher's `dontAutoconvertWordWithBackspace`, `dontAutoconvertWordWithDelete`, and arrow-key names as legacy aliases for imported settings, including the selector-shaped `dontAutoconvertWordWith...:` strings found in the binary. The observed name/selector anchors live in `PuntoSwitcherObservedSurface` and tests align the runtime aliases back to them. The observed legacy `cancellingKeys = 0` value is treated as an empty enabled-key mask, while non-zero legacy bit order remains intentionally unmapped until it can be proven. Backspace can suppress auto-correction for an edited token without hardcoding the preference into `WordTracker`, while Delete/navigation keys are represented in the same mask and continue to clear typed state before any stale auto-correction can be formed.
- `PuntoSwitcherObservedSurface`: reverse-audit-only selector/class/resource anchors that are useful to pin but should not own behavior. Accessibility preference selectors, Mail helper selectors, cancelling-key setter selectors, pasteboard timer/string selectors, hotkey editor selectors, input-source installer selectors, keyboard-layout private conversion selectors, product-statistic metric strings, old-rule source keys, search-click selectors, settings setter selectors, sound-state selectors, startup tooltip/window selectors, status-icon resource names, undo-learning popup/window identifiers, and user-rule UI selectors live here so behavior policies stay focused on native parsing and execution. Native aliases/log prefixes/metric names, import defaults, URL fragments, and sentinel values that are actually used at runtime live in the owning policy without the `observed` prefix and are aligned to reverse-audit anchors by tests; `Scripts/test-legacy-boundary.sh` rejects direct `PuntoSwitcherObservedSurface` references in the app shell and in the selected behavior-policy files.
- `LegacyValuePolicy`: shared plist/default-conf scalar parsing for native import policies. It centralizes Bool/NSNumber/string booleans, integer parsing, non-negative counters, Punto Switcher date strings, numeric date strings for the one legacy surface that already accepted them, and normalized bundle-id arrays so searchbar settings, update/install settings, product statistics, hotkeys, undo-learning, user rules, and settings aliases do not drift into subtly different legacy parsers.
- `AutoCorrectionRuleStore`: JSON and delimited-text import/export boundary for independently authored rules. It intentionally does not copy Punto Switcher dictionary resources.
- `AutoCorrectionRuleSourcePolicy`: native rule-source policy for Punto Switcher's `switcher.use_old_rules` / `switcherUseOldRules` signal: use independently authored starter rules until the user saves rules, preserve an intentionally empty saved list, and fall back to starter rules for unreadable persisted data. ## Current Conversion Flow

1. `HotkeyManager` keeps the system event tap alive and passes active keyboard/pointer events to `HotkeyEventRouter`. System tap-disabled events are routed through `EventTapLifecyclePolicy` and re-enable the CGEvent tap before returning the event.
2. `HotkeyEventRouter` feeds `flagsChanged` press/release snapshots into `ModifierOnlyHotkeyStateMachine`, which detects `Cmd+Opt+Shift` with debounce and keyDown cancellation. `keyDown` events are routed through `KeyDownEventPolicy`, including selected-text Yandex search shortcuts. Pointer down events are routed through `PointerEventPolicy` and clear `WordTracker` plus `ConversionSession`, preventing stale typed tails after clicks or cursor moves.
3. AX focus, focused-window, main-window, and window-created notifications from the active app are routed through `AccessibilityNotificationPolicy`; they clear typed text and undo state unless Punto is inside its own short replacement grace window. Selected-text and value-change notifications are subscribed for parity/diagnostics but do not clear typed state.
4. `AppDelegate.handleConvertLayout()` blocks disabled/security/password cases plus the Punto Switcher-style manual-conversion-disabled setting. This setting applies to layout conversion only; it does not globally disable tracking, auto-correction, or toggle-case.
5. `WordTracker` provides `lastTrackedWord` and `lastTrackedTail`.
6. `TextAccessor.captureSelectedText(...)` gathers AX/clipboard observations and passes them into `TextCapturePolicy.captureDecision(...)`, which chooses the replacement strategy:
   - editable AX selection -> AX replacement;
   - non-settable terminal-like selection -> rewrite tracked typed tail, including prompt-prefixed AX selections that end with that typed tail;
   - passive clipboard tail -> keyboard backspace + paste;
   - no safe evidence -> block.
7. `LayoutConverter.convertWithResult(...)` converts text and returns target layout.
8. Mixed or unknown non-convertible results are skipped before any replacement is attempted.
9. `ManualLayoutConversionPolicy` chooses the replacement route or cleanup action: selected text, terminal tail, last word, blocked capture, stale-tail cleanup, no text, or no-op skip. `ManualLayoutConversionRuntimePolicy` then turns that route into the branch-specific runtime plan: replacement labels, abort behavior, stale-state cleanup, and commit side effects.
10. `TextAccessor.replaceCapturedText(...)` applies the replacement and returns whether it actually sent a viable replacement path.
11. `TextReplacementPolicy` derives any tracked-tail update, selection-retention behavior, and undo replacement method from the actual successful replacement. Stale last-word tails are rejected instead of being rewritten blindly.
12. `ConversionSession` records the conversion for the 3 second undo window only after replacement reports success, and stores the active app context id with the record.
13. `Cmd+Opt+Delete` mirrors Punto Switcher's cancel-layout-change shortcut by invoking `UndoRuntimeCoordinator`, the same scoped undo executor that repeat-convert uses, so explicit cancellation and repeat-hotkey undo share replacement planning, terminal-tail replay, input-source restoration, sound feedback, redo-record updates, and the gated auto-correction undo-learning path.
14. `TextActionRuntimeCoordinator` optionally switches keyboard layout.
    Selected-text conversions pass through a separate selected-text switch gate, matching Punto Switcher's observed `switchLayoutOnSelectedTextSwitch` / `setSwitchLanguageWhenChangingSelectionLayout:` setting shape. Native settings read that legacy key as an import fallback.

## Current Auto-Correction Flow

1. `HotkeyManager` forwards ordinary key presses to `WordTracker`.
2. `SoundFeedbackPolicy` may emit typed EN/RU feedback for actual text input after disabled/security/password routing has allowed tracking.
3. `WordTracker` emits a one-shot completed token when a word is followed by Space, Return, Enter, Tab, or a configured hard separator.
4. `ApplicationReturnKeyPolicy` mirrors Punto Switcher's configurable `reset_on_return` bundle-token list. The native default is `telegram`; persisted settings override the token set, including an intentionally empty list, and the observed `switcher.reset_on_return` alias is accepted as an import fallback. Matching is by normalized bundle-id component, so glued suffixes such as `nottelegram` are not reset. `KeyTrackingRuntimePolicy` composes this with global/app routing and secure/password blocking so reset-on-return consumes completed-token statistics and clears undo before auto-correction, while ordinary key presses only clear stale undo after auto-correction had a chance to enter the replacement window.
5. `AutoCorrectionRuntimeCoordinator` consumes the completed token and asks `AutoCorrectionRuntimePolicy` for a gate plan before reading the preserved typed tail. Disabled/security/password/cancelled-token decisions stay in the policy layer, clearing text/undo state when secure input is detected. A Punto Switcher-style setting can suppress auto-correction when the completed-token separator is Return/Enter/Tab while leaving Space-triggered corrections active. Backspace-edited token suppression is driven by the native cancelling-key mask, matching the observed `dontAutoconvertWordWithBackspace` / `cancellingKeys` shape while preserving the buffer for manual conversion; Delete and arrow cancelling keys map through the same policy and keep their stale-state clearing behavior. Manual layout conversion can also mark the rewritten tracked token as suppressed for the next completion, mirroring the observed inverted `shouldNotAutoconvertAfterConvertion` setting and `dontAutoconvertWordAfterConvertion:` selector without applying that suppression to toggle-case or undo flows.
6. `AutoCorrectionEngine` checks `SettingsManager.autoCorrectionRules`.
7. If a rule matches, `TextAccessor.replaceRecentText(...)` deletes `word + separator` and pastes `replacement + separator`.
8. `TextReplacementPolicy.trackedTailAfterRecentTextReplacement(...)` rewrites the tracked tail when it matches the completed token, or discards stale tail context and keeps only the replacement token.
9. `ConversionSession` records the auto-correction in the active app context so the existing short undo path can revert it without crossing application boundaries. Undoing an auto-correction records an auto-correction redo origin, not a generic layout redo, so repeated hotkey toggles do not switch input sources. When undo learning is enabled, that undo can also remove the exact native rule that caused the correction.
10. `Cmd+Opt+A` mirrors Punto Switcher's auto-correction toggle shortcut: `HotkeyManager` consumes the configured hotkey, flips `SettingsManager.autoCorrectionEnabled`, and clears typed/undo state so stale pre-toggle tokens cannot be corrected under the new mode.

## Current Toggle-Case Flow

1. `HotkeyManager` routes `Cmd+Opt+Z` through `KeyDownEventPolicy`.
2. `AppDelegate.handleToggleCase()` blocks disabled/security/password cases and enters the same short protected replacement window as conversion.
3. `TextAccessor.captureSelectedText(...)` uses the same AX/clipboard/terminal-tail decision matrix as layout conversion.
4. `ToggleCaseConversionPolicy` chooses blocked capture, no text, skipped replacement, or an executable captured-text toggle runtime plan with keep-selection, failure cleanup, and commit side effects.
5. `TextAccessor.replaceCapturedText(...)` applies the same safe replacement method selected by the capture policy.
6. Terminal tail rewrites update `WordTracker` so subsequent conversions still have current typed-tail context.
7. `ConversionSession` records the toggle so the existing repeat-convert undo path can revert it inside the active app context.

## Current Application Context Flow

1. `AppDelegate` tracks the active external bundle id from `NSWorkspace.didActivateApplicationNotification`.
2. `ApplicationContextPolicy.activationAction(...)` decides whether the transition is Punto's own UI activation or a real external app switch.
3. Real external app switches clear both `WordTracker` and `ConversionSession` so typed tails and undo records cannot be applied in a different app.
4. Activating Punto's own settings/menu window preserves the last external app context so opening preferences does not destroy the current workflow.
5. `ConversionSession.undoCandidate(contextID:)` only returns records whose stored context id matches the current active app.
6. `ApplicationLayoutPolicy` prevents `didActivateApplication` from writing the newly active TIS layout into the previous app's memory slot; layout restore uses only the new external bundle id, is skipped for disabled applications, and avoids a redundant TIS switch when the remembered layout is already active.

## Current Input Source Flow

1. Programmatic layout switches set a short `ignoreInputSourceChangesUntil` window before calling TIS.
2. `InputSourceChangePolicy.action(...)` classifies TIS notifications as programmatic-switch noise, conversion-window noise, or a real user layout change.
3. Programmatic and conversion-window notifications return tested log messages and do not mutate typed/undo state.
4. Real user layout changes first offer the observed layout to per-app layout memory, then clear `WordTracker` and `ConversionSession` with policy-owned reasons so mixed-layout typed buffers cannot survive a manual layout switch.
5. Input-source preference changes route through `InputSourceChangePolicy.preferencesChangeAction()`, refresh selectable EN/RU source caches, clear typed/undo state, and log the refresh through a tested action.

## Auto-Correction Rule Formats

Rules are stored as JSON-encoded `AutoCorrectionRule` values in `UserDefaults`; persisted rules are normalized through `AutoCorrectionRuleStore` on read and write so stale snapshots cannot keep blank rules or duplicate triggers alive.
`AutoCorrectionRuleSourcePolicy` selects the effective rules: if the user has never saved rules, Settings returns `AutoCorrectionStarterCatalog.rules`; once rules are saved, even an intentionally empty list stays empty; unreadable persisted payloads fall back to the starter catalog.
The Settings window can import and export user rules. Import accepts:

- JSON arrays of `AutoCorrectionRule`.
- Plain text lines in `trigger<TAB>replacement` format.
- Optional columns: `matchMode` (`exact` or `caseInsensitive`) and `preserveCase` (`true`/`false`).
- `#` and `//` comment lines are ignored; malformed rows are skipped and reported.

Duplicate rules are normalized by `(matchMode, trigger)`, with trimmed triggers lowercased only for `caseInsensitive` rules; later imports override earlier entries.
Export writes the normalized effective rule set as JSON so user-authored rules can be backed up or moved without relying on private Punto Switcher dictionaries.

## Settings UI Boundaries

`SettingsWindowController` owns the main preferences window shell and editor lifecycle. Hotkey recorder lifecycle, shortcut collision handling, and reset actions live in `HotkeySettingsController`; General/Advanced rows, setting toggles, count labels, and managed-row actions live in `GeneralSettingsController`; shared glass-section/header construction lives in `SettingsSectionFactory`. Repeated app-specific subwindows are split into focused controllers:

- `DisabledApplicationsEditorController`: current-app exception editor backed by `SettingsManager.disabledApplicationBundleIDs`.
- `ResetOnReturnEditorController`: Return-key reset bundle-component editor backed by `SettingsManager.resetOnReturnBundleComponents`.

These subwindows own their own table views, row state, add/remove actions, and text editing. The main settings window receives only count-refresh callbacks, keeping exception/reset editing from growing another monolithic settings controller surface.

Activation restore is guarded so frontmost-app layout observations cannot corrupt the previous app's remembered layout. Settings also exposes the remembered layout snapshot so stale per-app records can be inspected, removed, or cleared.
- The observed screen saver engine bundle id is classified as a volatile system context for layout memory. App-context switching still clears text/undo state, but layout restore and remembered-layout writes are skipped for `com.apple.ScreenSaver.Engine`.
- App context isolation clears typed buffers and undo records on real external app switches, while preserving state when Punto's own window activates.
- Settings defaults, app-identity snapshots, and app-context snapshots are centralized at the persistence boundary, so stale `UserDefaults` values with whitespace, casing drift, blank app ids, blank reset-on-return tokens, or blank layout ids cannot leak into runtime policy or Settings UI. Missing reset-on-return settings use the native default; unreadable payloads fall back to the default; an explicitly saved empty list disables return-key resets for all bundle components. The Settings window exposes this list in the Return Reset Apps editor.
- Auto-correction has the event pipeline, rule engine, independently authored starter catalog, JSON/text import, JSON export, Settings import/export buttons, a Punto Switcher-style Enter/Tab trigger toggle, a Punto Switcher-style cancelling-key mask, a post-manual-conversion suppression toggle, and a native Settings rule editor table with search, validation status, and invalid-row highlighting. Manual conversion can be disabled independently from auto-correction and toggle-case.
- Auto-correction can be toggled with `Cmd+Opt+A`. `AutoCorrectionTogglePolicy` flips the persisted setting, clears typed/undo state, emits the user-visible log, and flashes the menu icon through an explicit action that the app layer executes.
- Disabled-app rules can be toggled from the menu bar for the last active app and managed from Settings. The toggle action and status-menu state are isolated in `ApplicationDisablePolicy`, refuse Punto's own bundle id, normalize the external app id, and clear typed/undo state only when the app is newly disabled. The same policy owns the toggle log shape so app code does not rebuild exception text ad hoc. By default, disabled-app exceptions suppress tracking and auto-correction while leaving manual conversion/search/toggle hotkeys available; the Punto Switcher-style full-disable setting makes those manual actions pass through too. The Settings editor can add the current app, remove selected apps, and resolve stored bundle IDs back to app names when possible.

## Refactor Direction

Keep app-facing behavior stable and extract testable policies one at a time:

1. Continue shrinking `TextAccessor` only where it still owns real transport orchestration; do not re-extract policy already isolated in `TextCapturePolicy`, `TextReplacementPolicy`, `Accessibility*Policy`, or the transport adapters.
2. Keep `HotkeyManager` as the event tap lifecycle owner. New modifier/key/pointer behavior belongs in `PuntoCore` policy plus `HotkeyEventRouter`, and `Scripts/test-legacy-boundary.sh` guards this split.
3. Keep broad scenarios in `PuntoCoreTest` / `PuntoParityTest` and delete new copy-based harnesses instead of reviving `PuntoTest`.
4. Add integration scripts only around real macOS surfaces, with explicit preconditions and log assertions.
