# Punto Switcher Reverse Notes

This is a read-only behavioral and architectural summary of `/Applications/PuntoSwitcher.app`.
It is not source code and should only guide native Swift implementation choices in this project.

- Bundle: `ru.yandex.desktop.PuntoSwitcher`
- Version: `2.1.5 (1724)`
- Architecture: `x86_64`
- Signed by: `Developer ID Application: Yandex, LLC (477EAT77S3)`
- Timestamp: `2018-08-17`
- UI mode: `NSUIElement=1`
- Sudden termination: `NSSupportsSuddenTermination=false`

## Imported macOS Capabilities

- Accessibility: `AXIsProcessTrusted`, `AXUIElementCopyAttributeValue`, `AXUIElementSetAttributeValue`, `AXSelectedText`, `AXSelectedTextRange`
- Event tap and synthetic keys: `CGEventTapCreate`, `CGEventPost`, `CGEventCreateKeyboardEvent`
- Keyboard layouts: `TISCopyCurrentKeyboardLayoutInputSource`, `TISCreateInputSourceList`, `TISSelectInputSource`
- Security guard: `IsSecureEventInputEnabled`
- Clipboard path: `NSPasteboard/generalPasteboard`
- File logging: CocoaLumberjack `DDFileLogger` / `DDFileLogManagerDefault` with `maximumNumberOfLogFiles` and `logFilesDiskQuota`

## Visible Class Boundaries

- `PuntoSwitcherCore`: event tap, raw text buffer, undo text buffer, pasteboard restore, selected-text processing, shortcuts.
- `ConversionEngine`: dictionaries, triggers, user rules, layout detection/conversion.
- `PuntoInputSourcesManager`: current input source, English/Russian layouts, switching.
- `ApplicationLayoutsManager`: per-application layout memory and disabled app checks.
- `AccessibilityController`, `AccessibilityElement`, `AccessibilityObserver`: focused element, selected text, AX notifications.
- `PuntoUndoManager`: cancellation/undo learning.
- `SettingsManager`: plist settings, shortcuts, disabled apps, user rules.

## Native Swift Direction

- Keep `TextAccessor` as an adapter over AX, pasteboard, and CGEvent primitives.
- Keep conversion, typed-buffer, capture policy, and undo/session state in `PuntoCore`.
- Model undo as a first-class `ConversionSession`, not fields inside `AppDelegate`.
- Model terminal/non-settable selection as a pure `TextCapturePolicy`.
- Add per-app layout memory and disabled-app rules as native Swift settings/runtime gates.
- Use dictionaries/triggers only if they are independently authored or user-provided; do not copy proprietary data files.

## Resource Configuration Signals

`Contents/Resources/default-conf.json` contains behavioral configuration that is safe to mirror structurally:

- `switcher.reset_on_return = ["telegram"]`: Telegram-like apps reset typed state on Return/Enter. Native Punto keeps its own editable `resetOnReturnBundleComponents` key but reads the observed `switcher.reset_on_return` alias as a fallback and mirrors writes to both keys.
- The observed plist stores `isAutocorrectionActive = 0`. Native Punto mirrors this fresh-install default by keeping auto-correction off until explicitly enabled, reads `isAutocorrectionActive` as a fallback when the native key is absent, and mirrors writes to both keys.
- The observed plist stores first-run state as `isFirstInstallation`. Native Punto keeps `isFirstLaunch` as its own key but reads `isFirstInstallation` as a fallback and mirrors writes to both keys.
- The binary exposes `--install`, `handleInstallArgument`, `openWindowAfterInstaller`, `showInstallationFinishedTooltip`, `showUpdateFinishedTooltip`, `tooltip-app-installed`, `shouldDisplayWelcome`, `Displaying welcome screen...`, and install/update flags around first-run handling. Native Punto mirrors this as `StartupPresentationPolicy`: an installer launch argument marks the app as just installed and exits any updating state; welcome is shown when the native first-launch flag, legacy first-install flag, or observed just-installed flag is set; then `isFirstInstallation` and `isJustInstalled` are consumed so the welcome path does not repeat. If an imported updater state still has `isJustUpdated`, Punto emits a native update-finished presentation log and consumes `isJustUpdated` / `isUpdating`. Native Punto uses its own short install/update-complete text instead of copying Punto Switcher's localized tooltip copy.
- The observed plist stores login startup as `launchesOnStartup`. Native Punto keeps its existing `launchAtLogin` setting but reads the legacy alias when the native key is absent and mirrors writes to both keys.
- The binary exposes `launchAccessibilityPreferences`, `openAccesibilityPrefPane:`, `accessibility-alert-message`, `accessibility-alert-messageLegacy`, the `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` URL, and a legacy AppleScript fallback that opens `System Preferences` and reveals the `Privacy_Accessibility` anchor under `com.apple.preference.security`. Native Punto mirrors this as `AccessibilityPreferencesPolicy`: it opens the observed URL first, falls back to the observed AppleScript shape only if the URL open call fails, and centralizes native Accessibility permission alert copy around the observed modern/legacy message keys without copying Punto Switcher's localized text.
- The binary and observed plist expose updater/install state keys: `configVersion`, `isJustInstalled`, `isJustUpdated`, `isUpdating`, `shouldCheckForUpdatesAutomatically`, `updateRequestRateInDays`, `lastStatisticsRequestDate`, `lastUpdateRequestDate`, and `lastUpdateShownDate`. Native Punto mirrors these through a tested settings-boundary snapshot so imported/exported defaults keep the observed shape (`configVersion = 8`, non-updating, automatic checks enabled, zero request rate, and the 2008-12-31 21:00:00 +0000 initial date markers). It intentionally does not implement Yandex network update checks or statistics upload.
- The observed plist and binary expose `showAdvancedSettings` / `setShowAdvancedSettings:`. Native Punto mirrors the same persisted flag and uses it to collapse advanced preferences in the Settings window by default, while still keeping the native settings model as the source of behavior.
- The binary also exposes `shouldNotAutoconvertWithTabOrEnter` / `setDontAutoconvertWithEnterOrTab:` preference names. Native Punto keeps auto-correction on Return/Tab enabled by default for current behavior, but exposes a separate tested setting so users can suppress Enter/Tab-triggered auto-correction while keeping Space-triggered corrections. The legacy key is inverted relative to the native setting and is read/written as such.
- The binary exposes `cancellingKeys`, `setCancellingKeyState:doEnable:`, and per-key names such as `dontAutoconvertWordWithBackspace`, `dontAutoconvertWordWithDelete`, and the four arrow-key variants. The installed app's observed defaults include `cancellingKeys = 0`; native Punto maps that value to an empty cancelling-key mask, but does not guess the non-zero bit order. Native Punto mirrors the structure with normalized names for `backspace`, `delete`, `leftArrow`, `rightArrow`, `upArrow`, and `downArrow`, and also accepts the observed `dontAutoconvertWordWith...` names as aliases when normalizing imported settings. Backspace keeps the typed buffer accurate for manual conversion but can mark the completed token as ineligible for automatic correction; Delete and navigation keys remain state-clearing guards so Punto does not auto-correct after cursor movement or destructive editing.
- The binary exposes `switchLayoutOnSelectedTextSwitch` and `setSwitchLanguageWhenChangingSelectionLayout:` around selected-text processing; the observed plist stores `switchLayoutOnSelectedTextSwitch = 1`. Native Punto mirrors this as a separate selected-text layout-switch gate layered under the global "switch keyboard after conversion" setting, reads the legacy key as a fallback, mirrors writes back to it, and pins the observed key/selector in settings policy, core tests, and reverse audit.
- The binary exposes `shortcutSwitchAutocorrection` / `switchAutocorrection`. Native Punto mirrors this with a configurable `Toggle Auto-correction` hotkey that flips the native auto-correction setting and clears typed/undo state.
- The binary exposes `shortcutCancelLayoutChange` / `cancelLayoutChangeShortcut` around layout-change cancellation. Native Punto mirrors this with a configurable `Cancel Last Conversion` hotkey that reuses the same conversion-session undo path as repeat-convert undo.
- The binary exposes `shortcutFindInYandex`, `shortcutFindInSlovari`, `processSelectedTextWithYandex`, `findInYandex`, `searchInYandexShortcut`, and URL templates for Yandex search/translate. Native Punto mirrors this structurally with configurable selected-text search shortcuts that are unassigned by default, plus a tested URL builder for `yandex.ru/yandsearch?text=...&clid=141986&yasoft=puntomac` and `translate.yandex.ru/?text=...&clid=141986`; it does not implement proprietary search suggestions or searchbar UI.
- `default-conf.json` stores `search.bar.offer = true`, `search.click.offer = false`, and `search.bar.sitesearch_prompt_cnt = 3`, while the binary exposes `PSSearchbarSettings`, `ActivationShortcut`, `Autoactivation`, `AutoactivationExceptions`, `AlertShownIn`, `ShouldSearchByDoubleClick`, and `SitesearchPromptCounter`. The binary also exposes click-search/window gates such as `canDoSearchClick`, `showSearchWindowAutomatically`, `showSearchWindowSelectedText`, and `setIsClickSearch:`. Native Punto mirrors this as tested settings-boundary and click-gate policy, preserves the observed key names for imported/exported defaults, including normalized exception bundle IDs and the observed `2009-01-01 00:00:00 +0300` initial alert date marker, exposes `ShouldSearchByDoubleClick` in advanced native settings, and routes enabled left-double-click search through live AX role capability plus the same selected-text Yandex search path as the explicit hotkey. It still treats proprietary searchbar suggestion UI as outside the native behavior surface.
- The observed plist stores shortcuts as dictionaries such as `shortcutChangeLayout`, `shortcutChangeCase`, `shortcutCancelLayoutChange`, `shortcutSwitchAutocorrection`, `shortcutFindInYandex`, and `shortcutFindInSlovari`, with `charKeycode` plus `isCommandUsed` / `isAltUsed` / `isShiftUsed` / `isControlUsed`; `charKeycode = 666` represents no physical key, which is either modifier-only when modifiers are present or unassigned when no modifiers are present. Native Punto keeps Codable `Hotkey` values as the primary store, but reads those legacy dictionaries as fallbacks and mirrors writes to the same shape.
- The binary exposes `doesCollideWithExistingShortcuts`, `shortcutField:canAllowShortcut:`, `emptyShortcut`, `isAllowedCharacterKeycode:`, and `isAllowedShortcutCharacterKeycode:` around shortcut editing. Native Punto mirrors the shortcut editor guard structurally: disabled/unassigned shortcuts can repeat, editing a shortcut ignores its own current assignment, assigning a shortcut already used by another action is rejected in the Settings UI, and modifier/Caps Lock/Fn/Escape keycodes cannot be stored as raw or shortcut character keycodes.
- The binary exposes `kbdLayoutType`, `setKbdLayoutType:`, `windowsLayoutUsed`, `englishLayoutID`, `russianLayoutID`, `setEnglishLayout:`, `setRussianLayout:`, `defaultEnglishLayout`, `defaultRussianLayout`, `inputSourceEnabled:`, `handleInputSourcesEnabled`, `promptUserToInstallLayouts`, `isAppleLayout`, `isDvorak`, `fixString:isEnglish:isApple:`, `createMacToPcMappingWithString:pcLayoutA:pcLayoutB:`, `convertStringLayout:withMode:isPCLayout:`, and knows `com.apple.keylayout.US`, `com.apple.keylayout.Dvorak`, `com.apple.keylayout.RussianWin`, and the `UNDEFINED` layout-id sentinel. Native Punto mirrors this as tested input-source preferences and variant classification: Mac is the default Russian layout type, the observed `kbdLayoutType = appl` legacy value maps to Mac, Windows/PC prefers `RussianWin` when it is installed, automatic English selection prefers default ABC/US layouts over variants such as Dvorak or USInternational, Dvorak and Apple-vs-Windows Russian source ids have explicit token-safe policy coverage, explicit EN/RU layout IDs can override automatic selection when they are installed/selectable/enabled, disabled sources are skipped, `UNDEFINED` is treated as no explicit preferred source, and selection falls back to automatic EN/RU discovery when a preferred source is unavailable or disabled. Manual text conversion now passes the selected Russian layout type into `LayoutConverter`: the legacy/default converter calls preserve the historical Windows/PC punctuation table, while the Mac-specific path uses observed local TIS/UCKeyTranslate evidence for `com.apple.keylayout.Russian` (backslash key -> `ё`, backtick -> `]`, shifted backtick -> `[`, and the Apple shifted number row). Runtime word tracking and post-replacement tail replay receive the same selected layout type, so Mac-layout physical punctuation that looks like a Windows separator, including backslash/pipe and shifted number-row symbols, remains part of the current wrong-layout word before and after conversion/undo-style rewrites. When required EN/RU layouts are unavailable or disabled, native Punto now emits a tested `promptUserToInstallLayouts`-shaped diagnostic instead of silently continuing with a half-configured input-source pair. Native settings read `kbdLayoutType`, `englishLayoutID`, and `russianLayoutID` as fallbacks and mirror unset writes to those legacy layout-id keys as `UNDEFINED`. The reverse-audit and core tests now pin the observed layout-conversion selector boundary, but native Punto does not yet guess Punto Switcher's private `fixString:isEnglish:isApple:` punctuation remapping beyond the public macOS layout table or private Mac-to-PC conversion tables without stronger behavioral evidence.
- The binary logs failed input-source activation and has a guard for `TISSelectInputSource` returning success while the current layout stays unchanged (`Tried to switch to layout ... but layout stayed the same`). Native Punto mirrors this by verifying the current TIS source id after every programmatic layout switch and treating a stale current layout as a failed switch, so undo/layout-memory bookkeeping does not record a switch that macOS did not actually apply.
- The binary exposes `shouldNotAutoconvertAfterConvertion` / `dontAutoconvertWordAfterConvertion:` around post-manual-conversion suppression. Native Punto mirrors the behavior as `suppressAutoCorrectionAfterManualConversion`: manual layout conversion can mark the rewritten tracked token as ineligible for the next completed-token auto-correction, while toggle-case, undo, and auto-correction redo keep their existing behavior. The legacy key is inverted relative to the native setting and is read/written as such; both the key and selector are pinned in the native settings policy and reverse audit so this boundary cannot silently drift.
- The binary exposes `isManualConversionDisabled` / `setIsManualConversionDisabled:`. Native Punto keeps `manualConversionDisabled` as the primary key, reads `isManualConversionDisabled` as a fallback, and mirrors writes to both keys. The behavior remains a separate manual-conversion gate: layout conversion hotkeys are skipped while tracking, auto-correction, toggle-case, and global enablement remain independent. The observed key/selector are pinned in settings policy, core tests, and reverse audit.
- The binary carries `punto.SecureInput.plist` and secure-input diagnostic fields/log strings for `SecureInputState`, `Context`, `currentApp`, `runningApps`, and `enabledLayouts`. Native Punto already blocks secure/password text interaction; it now also writes a normalized diagnostic plist with the same observed field names when secure/password state forces tracked text and undo state to be cleared.
- The binary exposes `undoLearning`, `undoCollectionEnabled`, `undoDictionary`, and `mustShowUndoWindow`; the observed plist stores `undoCollectionEnabled = 0`, `mustShowUndoWindow = 1`, and an empty `undoDictionary`. Native Punto mirrors the behavioral core as an `autoCorrectionUndoLearningEnabled` setting: when enabled, undoing an auto-correction removes the exact native rule that produced it; the default remains off to match the observed preference. Native Punto also mirrors the full nested settings shape through `UndoLearningSettingsPolicy`, preserving `mustShowUndoWindow` and normalized `undoDictionary` values for import/export compatibility. It does not recreate Punto Switcher's proprietary undo-learning popup UI.
- The binary exposes `shouldRememberInputSourceForEachApp` for per-app layout memory, plus `disabledApps`, `setDisabledApplications:`, `disabledAppsPreferencesController`, `setDisabledAppsPreferencesController:`, and `CompletelyDisableInExceptionApps` for exception apps. Native Punto keeps descriptive native keys for these settings, but reads the Punto Switcher-style aliases as fallbacks and mirrors writes. Exception apps suppress typed tracking and auto-correction by default, while manual text actions remain available unless full-disable mode is explicitly enabled. The observed exception/per-app settings surface is pinned in settings policy, core tests, and reverse audit.
- The binary carries `com.apple.ScreenSaver.Engine`. Native Punto treats that bundle id as a volatile system context for per-app layout memory: activating the screen saver still clears stale typed/undo state through the ordinary app-context change path, but Punto does not restore or persist remembered keyboard layouts for the screen saver engine.
- The binary exposes local product counters such as `TypedWords`, `TypedSymbols`, `AutoSwitches`, `ManualSwitches`, and `Reverts` under `PSDayuseSettings`, plus `PSDayuseStat`, `LastDayuseDate` / `LastProductStatDate`, setter/accessor names, and `product.typed.symbol` / `product.typed.word` metric strings. Native Punto mirrors these as local `ProductStatisticsSnapshot` counters in UserDefaults, incremented for typed symbols, completed words, successful auto-corrections, successful manual layout conversions, and successful undo/revert operations. It also reads/writes the nested Punto Switcher-style `PSDayuseSettings` dictionary, date stamps, and individual native-compatible counter keys for compatibility with the observed settings shape. The observed key/selector/metric boundary is pinned in `ProductStatisticsPolicy`, `PuntoCoreTest`, and reverse audit. It does not implement Yandex network statistics upload.
- The binary exposes `userRulesDictionary` and user-rule fields such as `rule_string`, `rule`, `is_active`, `do_replace`, and `is_regexp`, plus create/modify/remove rule methods and `showWordAddedTooltip:`. Native Punto reads this legacy array when no native auto-correction rules have been saved, imports only active non-regexp replacement rules with non-empty trigger/replacement fields, and layers them on top of the native starter catalog. Native rule writes also mirror the normalized rules back into the observed `userRulesDictionary` shape with active, non-regexp replacement flags. Empty or unsupported legacy shapes do not disable starter rules.
- `switcher.use_old_rules = true`: bundled dictionary/rule behavior exists, and the binary also exposes the `switcherUseOldRules` accessor. Native Punto keeps independently authored starter rules and user imports instead of copying `ps.dat` or `triggers.dat`, while pinning both observed old-rules signals in tests/audit. The old-rules flag defaults on; when an imported plist explicitly sets it off before native rules have been saved, native Punto skips the starter catalog but still accepts imported user rules.
- Browser accessibility groups split `inject` and `eui`: the observed `inject` list includes Safari, Chrome/Chromium, Opera, Firefox, and Yandex Browser, while the observed `eui` list includes Chrome/Chromium, Opera, Firefox, and Yandex Browser but not Safari. Native Punto keeps replacement decisions capability-based through AX/WebArea and clipboard fallback, preserves both lists as tested bundle-id policy, and attempts `AXEnhancedUserInterface` only for the observed `eui` bundle ids.
- The binary exposes AX notification names for focused element, focused window, main window, window creation, selected text, and value changes. Native Punto subscribes to the same notification surface where the target app supports it, but only focus/window creation changes clear typed state; selected-text and value-change notifications are retained as non-clearing diagnostics so ordinary text entry does not erase the conversion buffer.
- Search/click role exceptions distinguish editable roles (`AXTextField`, `AXTextArea`, `AXComboBox`) from navigation/static/list roles across Finder, Xcode, Chrome/Chromium, Firefox, Mail, Telegram, and system apps. Native Punto does not implement search suggestions, but it mirrors the observed global/app-specific role matrix as `AccessibilityRolePolicy` data for future UI gates, and it treats pointer clicks as typed-tail invalidation so stale pre-click buffer state cannot be converted at a new cursor location.
- The binary exposes pasteboard restoration controls (`shouldRestorePasteboard`, `previousPasteboardContents`, `pasteboardRestoreTimer`, `generalPasteboard`, `getPasteboardString`, `setPasteboardString:`, `restorePasteboardByTimer:`, and `restorePasteboardForKeyboardByTimer:`). Native Punto keeps its full pasteboard snapshot/restore implementation default-on, reads and writes the Punto Switcher-style `shouldRestorePasteboard` alias through the native `restorePasteboardAfterConversion` setting, and applies that gate consistently to Cmd+C capture fallback, selected-text clipboard replacement, and keyboard-tail paste replacement. The observed key/selector boundary is pinned in `ClipboardReplacementPolicy`, `PuntoCoreTest`, and reverse audit.
- The binary exposes Mail-specific replacement helpers (`applyMailBehaviourForFullWords...`, `applyMailBehaviourForPartialWords:`, `numberOfDeletionsInMail`) and carries `Mail`, `com.parallels.desktop`, and `AXScrollArea` strings near those helpers. Native Punto does not guess the full private coordinate/deletion algorithm, but it now treats `AXScrollArea` as a non-editable content role and allows clipboard-backed selected-text replacement there only when active copy returns the same selected text, matching the same safety shape already used for `AXWebArea`.

## Sound Feedback Signals

Punto Switcher bundles short sound resources: `replace.wav`, `reverse.wav`, `misprint.wav`, `switch.wav`, `en.wav`, `ru.wav`, `typeeng.wav`, and `typerus.wav`, and exposes an `enabledSounds` bitmask plus `isSoundOn`/`setSoundState:isSoundOn:` settings path. The observed plist stores `enabledSounds = 502` while global sound is off. The binary also exposes per-event legacy toggles: `useSoundLayoutSwitchToRussian`, `useSoundLayoutSwitchToEnglish`, `useSoundConvertation`, `useSoundMisprint`, `useSoundAutocorrection`, `useSoundUndo`, and `useSoundKeystrokes`. Native Punto mirrors this as event-to-resource-name policy, a global sound-enabled setting that defaults off like the observed `isSoundOn = 0` preference, reads `isSoundOn` as a fallback, per-resource sound toggles, a tested legacy bitmask bridge in the bundled resource order, tested import/export of the observed `useSound...` toggles, and independently generated short WAV resources with the same structural names, including typed EN/RU feedback decisions, but does not copy the proprietary audio files.
The binary also exposes a `shouldSkipNextLanguageChangeSound` state around layout switching. Native Punto mirrors that structurally by suppressing `en`/`ru` input-source switch sounds when the switch is caused by text replacement or remembered per-application layout restore, so conversion/undo/toggle feedback and automatic app-activation TIS restores do not stack with a second layout-change sound.

## Menu Bar Icon Signals

Punto Switcher bundles status item icon variants `icon_active.tiff`, `icon_inactive.tiff`, `icon_disabled.tiff`, plus `_w` white variants, and exposes `updateMenubarIcon:` near `isEnabled` and current-application-disabled checks. Native Punto mirrors the same state split as `StatusIconPolicy`: globally enabled/external app is active, globally disabled is inactive, and enabled-in-general-but-disabled-for-current-app is disabled. The native app keeps its own template menu bar artwork and applies state tint/tooltip rather than copying proprietary icon files.

## Logging Signals

Punto Switcher initializes a bounded file logger through CocoaLumberjack and exposes `maximumNumberOfLogFiles` / `logFilesDiskQuota` knobs in the binary. Native Punto keeps its simple `/tmp/punto.log` debug surface for scripts, but now routes rotation through a tested `LogRetentionPolicy`: active logs rotate when they exceed the native max size, archived logs use deterministic Punto-style filenames, and old archives are pruned by count and total disk quota.
